# HER Excerpts for Chapter 30: AppState: The Redux-like Store

## §21 Layer 2 — Session Management

### Layer 2: Session Management
- Session startup protocol (orient -> setup -> verify -> select)
- Clean exit protocol (update state -> commit -> persist notes)
- Session-to-session handoff via structured files
- Maximum session duration limits with graceful wind-down

The AppState store is the in-memory representation of Layer 2 in the reference architecture. It holds the current session's mutable state: the active task, the conversation history, the permission mode, the tool availability, and the UI state. The store follows a Redux-like pattern:

- **Single source of truth**: All session state lives in one store
- **Immutable updates**: State changes through dispatched actions, not direct mutation
- **Subscribers**: UI components and hooks subscribe to state changes
- **Reducers**: Pure functions that compute the next state from the current state and an action

This architecture ensures that the session can be persisted (serialized to JSONL) and restored (deserialized back into the store) without loss of information. The clean exit protocol maps directly to serializing the store and writing it to disk; the startup protocol maps to deserializing the store and re-orienting the agent.

The Redux-like pattern also enables time-travel debugging: by recording the sequence of actions, the harness can replay any session to reconstruct the exact state at any point in time. This is essential for debugging multi-hour tasks where the agent's behavior diverged from expectations at an unknown point.
