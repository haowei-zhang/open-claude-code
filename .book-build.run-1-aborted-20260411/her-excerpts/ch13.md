# HER Excerpts for Chapter 13: File System Tools: Read, Write, Edit, Glob, Grep, Notebook

## §5 Pattern 11 — Single-Purpose Tool Design

**Single-Purpose Tool Design**: FileReadTool, FileEditTool, GrepTool each with individual permission rules

Each tool has a single, well-defined responsibility. Rather than a monolithic "file operations" tool, the harness provides separate tools for reading, writing, editing, searching, and globbing. This enables:

- **Granular permission control**: Each tool can be individually allowed, denied, or gated behind user approval
- **Clear failure boundaries**: When a tool fails, the failure is isolated to its specific operation
- **Targeted risk classification**: Dangerous operations (write, edit) can have stricter approval requirements than safe ones (read, grep)
- **Independent evolution**: Tools can be modified, added, or removed without affecting others

## §6.4 — Placeholder Implementations

- **Symptom**: Agents default to stubs because compiling triggers reward signals
- **Fix**: Explicit anti-placeholder instructions ("DO NOT IMPLEMENT PLACEHOLDER OR SIMPLE IMPLEMENTATIONS")

Geoffrey Huntley's Ralph system uses forceful language: "DO NOT IMPLEMENT PLACEHOLDER OR SIMPLE IMPLEMENTATIONS. WE WANT FULL IMPLEMENTATIONS." The file-editing pipeline must guard against agents writing stub functions, TODO comments, or incomplete implementations that pass initial checks but fail in production. The harness can enforce this through:

- Post-edit hooks that detect placeholder patterns (TODO, FIXME, stub, pass, NotImplementedError)
- Test execution after edits that verifies the code actually works
- Linter rules that flag common placeholder patterns

## §6.15 — Data Leakage Between Contexts

- **Symptom**: Information leaks between sessions, between sub-agents, or through file-based communication
- **Evidence**: File-based communication (recommended in Section 9.3) inherently persists data to disk. Without cleanup, sensitive data from one task context can bleed into another.
- **Fix**: Context isolation via separate file namespaces; cleanup protocols; avoid logging sensitive data in progress files; use ephemeral directories for sensitive work.

For file system tools, data leakage risk is acute: the tools read and write files that persist across sessions. A file written during one task may be read by an agent working on an unrelated task, causing cross-contamination of context. The harness must enforce directory scoping and prevent agents from reading files outside their designated workspace.
