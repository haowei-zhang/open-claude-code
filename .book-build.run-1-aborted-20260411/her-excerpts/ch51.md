# HER Excerpts for Chapter 51: Debug Logs, Diagnostics, and Doctor

## §14.2 — The Observability Gap

Agents fail silently because their response format looks correct. A 200 OK from a tool call doesn't mean the operation succeeded semantically. Observability must go beyond "did the API call return?" to "did the operation achieve its intended effect?"

This gap is the central challenge for debug logging and diagnostics. The harness must distinguish between:
- **Structural success**: The tool call completed without errors (200 OK, exit code 0)
- **Semantic success**: The tool call achieved its intended purpose (the bug was actually fixed, the file was correctly edited)

Debug logs must capture not just what happened but whether it achieved the intended effect. This requires:
- Structured logging that captures intent alongside outcome
- Post-hoc verification steps that confirm semantic success
- Diagnostic tools that can replay a session and identify where semantic failures occurred

## §6.6 — Silent Failures

- **Symptom**: Agent proceeds after tool errors as if successful
- **Fix**: Structured output validation after every tool call

Silent failures are a direct consequence of the observability gap. The agent treats structural success as semantic success. The doctor diagnostic tool must detect silent failures by:

- Re-running verification steps after the agent claims completion
- Comparing the agent's claimed outcomes against actual state
- Flagging discrepancies between what the agent reported and what the tools actually returned
- Providing a structured failure report that the agent can use for self-correction
