# HER Excerpts for Chapter 46: Worktrees: Isolated Parallel Branches

## §5 Pattern 8 — Fork-Join Parallelism

**Fork-Join Parallelism**: Multiple subagents in isolated git worktrees; cached parent context reuse

The fork-join pattern enables parallel execution of independent tasks:

1. **Fork**: The parent agent spawns multiple sub-agents, each in its own isolated worktree with a cached copy of the parent's context
2. **Execute**: Sub-agents work in parallel on independent tasks without interfering with each other
3. **Join**: Results from all sub-agents are merged back into the parent's context

Key design decisions:
- Git worktrees provide filesystem isolation
- Parent context is cached and shared (not re-constructed for each sub-agent)
- Only results (not intermediate context) flow back to the parent
- The parent orchestrates the join, resolving any conflicts

Worktrees are the filesystem-level isolation mechanism for fork-join parallelism. Each worktree provides:
- A separate working directory with its own copy of the repository
- Isolated git state (branches, commits, staging area)
- Shared commit history (worktrees share the same .git directory)
- Symlinked node_modules (to avoid duplicating dependencies)

## §12.4 — Path Traversal Defense

**Data Exfiltration Through Tool Calls** (related): The harness must prevent agents from accessing files outside their designated workspace.

For worktrees, path traversal defense is critical because:
- Each sub-agent operates in its own worktree directory
- The sub-agent must not be able to escape the worktree and access the parent's files
- Symlinked directories (like node_modules) must not provide traversal paths
- The EnterWorktreeTool must validate worktree paths against path traversal attacks

The harness enforces this through:
- Path validation on all file operations within worktrees
- Symlink resolution to detect traversal attempts
- Directory scoping that restricts each sub-agent to its worktree root
- Audit logging of any attempted path violations
