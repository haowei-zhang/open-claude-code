# HER Excerpts for Chapter 36: The Hook Schema and Lifecycle Events

## §5 Pattern 12 — Deterministic Lifecycle Hooks

**Deterministic Lifecycle Hooks**: Shell commands at 25+ lifecycle points (PreToolUse, PostToolUse, SessionStart, etc.)

Lifecycle hooks are deterministic shell commands that run at defined points in the agent's execution. Key properties:

- **Deterministic**: Same input always produces the same behavior (unlike model-generated decisions)
- **Blocking**: The pipeline waits for hook completion before proceeding
- **Exit-code semantics**: Non-zero exit can block the action, modify the input, or log a warning
- **Composable**: Multiple hooks can chain at the same lifecycle point

Hook types include:
- **Command hooks**: Execute a shell command; exit code 0 = proceed, 2 = block, other = error
- **Prompt hooks**: Modify the prompt before it reaches the model
- **HTTP hooks**: Call an external service; response determines whether to proceed
- **Agent hooks**: Invoke a sub-agent to make the decision
- **Function hooks**: Execute in-process TypeScript code

Common patterns:
- Auto-format after file edits (PostToolUse)
- File protection via PreToolUse
- Premature-completion prevention via Stop hooks
- Quality gates via TaskCompleted hooks

## §7 — Configuration Surfaces

Hooks are one of the six configuration surfaces (§7.5). The hook schema defines:

- Which lifecycle events support hooks
- The payload structure for each event
- The expected return format (proceed/block/modify)
- The execution order when multiple hooks are registered for the same event
- Error handling when a hook fails

The hook configuration is managed through settings files, making it part of the settings cascade. Project-level hooks override user-level hooks, which override org-level hooks. This allows teams to enforce organization-wide quality gates while enabling project-specific customizations.
