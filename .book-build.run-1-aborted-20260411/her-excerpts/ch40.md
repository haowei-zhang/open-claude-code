# HER Excerpts for Chapter 40: MCP: Clients, Transports, and Lifecycle

## §7.2 — MCP Servers

- Extend capabilities with external tool access
- "Too many tools is bad" -- excess tool descriptions push agents into "the dumb zone" faster
- If an MCP server duplicates CLI functionality well-represented in training data, use the CLI instead
- **Security note**: MCP servers are a supply chain attack surface. Treat them like untrusted npm packages.

MCP servers extend the harness's tool surface through the Model Context Protocol. Each MCP server provides additional tools that the agent can call, but each also adds:

- **Tool descriptions** to the system prompt (consuming context budget)
- **Attack surface** through the server's network access
- **Failure modes** if the server becomes unavailable or returns unexpected data
- **Latency** from server initialization and tool execution

The lifecycle of an MCP connection includes: discovery, initialization, tool registration, authentication (if required), tool execution, error handling, reconnection, and graceful shutdown. Each phase must be managed carefully to avoid context pollution and security vulnerabilities.

## §12.4 — Supply Chain via MCP

**Supply Chain Attacks via MCP Servers**: Compromised or malicious MCP servers can exfiltrate data, modify behavior, or escalate privileges.
- **Mitigation**: Vet all MCP servers; restrict tool permissions to minimum required; audit tool call logs; run tools in sandboxed environments when possible.

MCP servers are the most dangerous supply chain attack surface because they:
- Execute arbitrary code in separate processes
- Have network access (can exfiltrate data to external services)
- Provide tool definitions that the model trusts implicitly
- Can manipulate tool results to influence agent behavior

The harness must apply defense-in-depth: input validation on all MCP tool results, output filtering before results enter the context, audit logging of all MCP tool calls, and network restrictions on MCP server processes.

## §6.15 — Data Leakage

- **Symptom**: Information leaks between sessions, between sub-agents, or through file-based communication.
- **Fix**: Context isolation via separate file namespaces; cleanup protocols; avoid logging sensitive data in progress files; use ephemeral directories for sensitive work.

MCP servers can leak data between contexts. If a server maintains state across tool calls (e.g., a database connection), data from one agent's query may be visible to another agent using the same server. The harness must ensure that each MCP connection is isolated per session, or that the server implements proper multi-tenancy.
