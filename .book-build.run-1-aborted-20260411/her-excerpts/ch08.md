## §13 — Cost Management (Observation Masking)

### Cost Optimization Strategies

1. **Semantic routing**: Route simple sub-tasks (summarization, classification) to cheap models (Haiku); reserve expensive models (Opus) for planning and complex reasoning
2. **Observation masking**: 52% cost reduction by hiding irrelevant tool outputs (JetBrains Research, verified)
3. **Sub-agent isolation**: Research in cheap-model sub-agents rather than expensive parent context
4. **Early termination**: Kill sessions that are clearly stuck (loop detection, no-progress-for-N-minutes)
5. **Token metering**: Real-time tracking of input/output tokens per session, per task, per agent

### Cost Control Architecture

```
Per-task cost cap         -- Hard limit; task fails gracefully if exceeded
Per-session cost cap      -- Prevents runaway sessions
Per-hour spend rate alert -- Anomaly detection on spend velocity
Dead-letter queue         -- Tasks exceeding thresholds get queued for human review
Budget allocation         -- Separate budgets for generator/evaluator/sub-agents
```

### Observation Masking Detail

Observation masking is the single most effective cost optimization with verified evidence. By suppressing successful tool outputs (swallowing the result and only surfacing errors), the harness reduces the token count sent to the model by 52%. This means fewer input tokens per query iteration, which compounds over an entire session. The principle: "success is silent; only failures produce verbose output."

## §6.14 — Model Regression from Provider Updates

- **Symptom**: When a provider updates a model, harness behavior breaks silently. The harness was tuned for specific model behaviors that changed.
- **Evidence**: The report's own Principle 9 ("simplify as models improve") acknowledges positive evolution but not the negative direction.
- **Fix**: Regression test suite for the harness against model changes; pin model versions where stability matters; monitor key metrics after provider updates.

This is an underappreciated risk for the API layer. When Anthropic updates a model (e.g., Opus 4.5 to 4.6), the streaming protocol, token counting, retry behavior, and prompt cache semantics may all change subtly. The API wrapper must be defensive against these changes.
