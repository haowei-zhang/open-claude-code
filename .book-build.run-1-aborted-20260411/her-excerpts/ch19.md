# HER Excerpts for Chapter 19: Sync vs Fork vs Remote: The Execution Modes

## §9.1 — Three Tiers of Multi-Agent Orchestration

1. **In-Process Subagents**: Same process, isolated context windows (e.g., Claude Code's Agent tool)
   - Lowest latency, shared process resources
   - Context isolation via separate context windows, not separate processes
   - Best for: short, well-scoped sub-tasks (search, analysis, formatting)

2. **Local Orchestrators**: Separate processes coordinated by a parent (e.g., Ralph loop spawning multiple Claude instances)
   - Process-level isolation, no shared state
   - Communication via filesystem (files, git)
   - Best for: parallel exploration, background tasks

3. **Cloud Async**: Distributed agents with message-passing (e.g., remote triggers, webhook-based coordination)
   - Network-level isolation, geo-distributed possible
   - Communication via APIs and message queues
   - Best for: long-running tasks, cross-service coordination, scalable parallelism

## §6.5 — Context Anxiety

- **Symptom**: Models prematurely wrap up near perceived context limits
- **Fix**: Context resets with structured handoffs rather than pushing to the limit

Context anxiety is particularly relevant for execution mode selection. In-process sub-agents are most susceptible because the parent can see how much context has been consumed and may become "anxious" about approaching limits. Forked and remote agents, with their isolated contexts, don't face this issue for the parent -- but each sub-agent may experience its own context anxiety within its isolated window.

The fix is consistent across all tiers: use structured handoffs rather than trying to squeeze maximum work from a single context window. When a sub-agent (of any tier) approaches its context limit, it should write a structured summary and exit cleanly, rather than rushing to complete prematurely.
