# HER Excerpts for Chapter 28: Compaction Hierarchy: Five Stages of Context Rescue

## §5 Pattern 5 — Progressive Context Compaction

**Progressive Context Compaction**: Four layers: HISTORY_SNIP, Microcompact, CONTEXT_COLLAPSE, Autocompact

As the conversation grows, the harness progressively compacts older context to keep the working window manageable. The four layers activate at increasing token thresholds, each more aggressive than the last:

1. **HISTORY_SNIP**: Lightweight -- marks old tool outputs as summarized
2. **Microcompact**: Compresses individual tool results into concise summaries
3. **CONTEXT_COLLAPSE**: Aggressive -- replaces entire conversation segments with summaries
4. **Autocompact**: Full reset -- clears context and starts fresh with a structured handoff

cc adds a fifth stage: **Hard Reset**, which is the last resort when all compaction strategies have failed.

## §8 — Context Management Strategies

### Six Techniques (Synthesis)

1. **Observation Masking** (strong cost-efficiency evidence): 52% cost reduction by hiding irrelevant tool outputs
2. **LLM Summarization**: Use a cheaper model to compress verbose outputs before injecting into main context
3. **Progressive Compaction**: 5-stage system at configurable token thresholds
4. **Structured Note-Taking**: Agent maintains its own progress notes in files, which survive context resets
5. **Sub-Agent Isolation**: Research happens in separate context windows, only findings return to parent
6. **Per-Tool-Type Summarization**: Different compression strategies for different tool outputs (build logs vs. file reads vs. search results)

## §8.1 — Observation Masking (52% Cost Reduction)

**Observation Masking**: 52% cost reduction by hiding irrelevant tool outputs (JetBrains Research, verified). "Swallow the output and only surface errors."

Observation masking is the single most effective context management technique with verified evidence. The principle is simple: when a tool succeeds, its verbose output is hidden from the model. Only errors and warnings are surfaced. This dramatically reduces the token count per query iteration, which compounds over an entire session.

The compaction hierarchy uses observation masking at every stage. Before compaction even begins, the harness suppresses successful tool outputs. This reduces the volume of content that needs to be compacted, making each compaction pass more effective.

## §6.1 — Context Rot

- **Symptom**: Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.
- **Fix**: Active context management (summarization, pruning, progress file pattern)

The compaction hierarchy is the primary defense against context rot. By proactively compacting context before degradation becomes severe, the harness prevents the 30%+ performance drop that occurs when key content falls into the "dead zone" of mid-window positions. The five stages provide escalating rescue mechanisms, each triggered at a different severity threshold.
