# HER Excerpts for Chapter 34: Filesystem Permissions and Path Guards

## §12.4 — Data Exfiltration

**Data Exfiltration Through Tool Calls**: Agent sends sensitive data to external services via tool calls (API requests, file uploads, etc.).
- **Mitigation**: Allowlist external endpoints; monitor tool call parameters for sensitive data patterns; require human approval for external communications.

Filesystem permissions are the first line of defense against data exfiltration. By restricting which directories the agent can read and write, the harness limits the scope of data the agent can access (and potentially exfiltrate). Key defenses:

- **Path allowlists**: Only specified directories are accessible
- **Symlink traversal prevention**: Prevent the agent from following symlinks outside the allowed directory tree
- **Denial tracking**: Record every denied file access attempt for audit and anomaly detection
- **Glob allow/deny**: Fine-grained control over which file patterns are accessible

## §6.15 — Data Leakage

- **Symptom**: Information leaks between sessions, between sub-agents, or through file-based communication.
- **Evidence**: File-based communication (recommended in Section 9.3) inherently persists data to disk. Without cleanup, sensitive data from one task context can bleed into another.
- **Fix**: Context isolation via separate file namespaces; cleanup protocols; avoid logging sensitive data in progress files; use ephemeral directories for sensitive work.

Filesystem permissions enforce context isolation at the directory level. By ensuring that each session, sub-agent, or task operates within its own directory namespace, the harness prevents data leakage through the filesystem. The permission model must prevent:

- An agent reading files from a previous session's working directory
- A sub-agent accessing the parent's scratch files
- Concurrent tasks interfering with each other's file state
- Symlink-based escapes from the allowed directory tree
