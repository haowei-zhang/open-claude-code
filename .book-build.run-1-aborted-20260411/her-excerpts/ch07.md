# HER Excerpts for Chapter 07: The Query Loop: Heartbeat of the Agent

## §5 Pattern 6 — Explore-Plan-Act Loop

**Explore-Plan-Act Loop**: Three phases with escalating permissions (read-only -> discussion -> full access)

This pattern structures the agent's core execution loop into three distinct phases:
1. **Explore**: Read-only access. Agent gathers information, reads files, searches code. No mutations permitted.
2. **Plan**: Discussion mode. Agent proposes changes, discusses approach with user. Still no writes.
3. **Act**: Full access. Agent implements the plan, writes files, runs commands.

The escalating permissions ensure the agent has sufficient context before taking destructive actions. This directly maps to cc's plan mode V2 which gates tool availability by phase.

## §6.1 — Context Rot

- **Symptom**: Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.
- **Fix**: Active context management (summarization, pruning, progress file pattern)

Context rot is one of the most pernicious failure modes because it degrades gradually. The agent doesn't crash -- it just becomes progressively less reliable, re-solving problems it already addressed, contradicting earlier conclusions, and losing track of the original goal. The query loop must actively detect and mitigate rot through compaction, progress tracking, and periodic context resets.

## §6.2 — Premature Completion

- **Symptom**: Agent declares work done too early
- **Fix**: Comprehensive JSON feature list with all items initially marked "failing"

The agent's tendency toward premature completion is exacerbated in the query loop because each iteration produces visible output that feels like progress. Without explicit completion criteria (JSON feature lists with boolean pass/fail fields), the agent will declare victory prematurely.

## §6.7 — Infinite Loops

- **Symptom**: Retry without progress
- **Fix**: Maximum retry counts, exponential backoff, loop detection

Infinite loops are particularly dangerous in the query loop because each iteration consumes tokens and time. The harness must implement:
- Maximum iteration counts per session
- Exponential backoff on repeated tool failures
- Semantic loop detection (same tool called with same parameters N times in M minutes)
- Progress detection (no meaningful state change after N iterations)
