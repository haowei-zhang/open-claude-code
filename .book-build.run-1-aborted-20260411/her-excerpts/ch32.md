# HER Excerpts for Chapter 32: The Permission Model: Modes and Rules

## §12 — Guardrails

### Five-Layer Defense-in-Depth (§12.1)

1. **Prompt-level guardrails**: Instructions in system prompt about what not to do
2. **Schema-level restrictions**: Tool parameter validation, allowlists
3. **Runtime approval system**: Human-in-the-loop for destructive operations
4. **Tool-level validation**: Per-tool safety checks before execution
5. **Lifecycle hooks**: Deterministic shell commands at lifecycle events

### GUARDRAILS.md Protocol (§12.2)

Uses a **Sign** structure:
- **Trigger**: When this guardrail activates
- **Instruction**: What the agent must do
- **Reason**: Why this guardrail exists
- **Provenance**: Who added it and when

### Four Universal Safety Patterns (§12.3)

1. **Artifact Verification**: Check that generated outputs meet structural requirements before proceeding
2. **Context Rotation**: Periodically reset context to prevent degradation-induced errors
3. **Privilege Boundaries**: Different agents have different permission levels (research agents can't edit)
4. **Rate Limiting**: Prevent runaway loops and excessive API/tool usage

## §11 — Human-in-the-Loop

The permission model implements human-in-the-loop patterns through its modes:

### 11.2 Tiered Escalation
- **Tier 1** (automated): Deterministic checks handle (linting, testing, formatting)
- **Tier 2** (agent self-correction): Agent gets feedback from Tier 1 and tries again
- **Tier 3** (human front-line): Moderate-risk decisions
- **Tier 4** (human expert): High-risk decisions (architecture changes, security-sensitive operations, production deployments)

Permission modes map to these tiers: default mode requires Tier 3/4 for most operations; auto mode pushes most decisions to Tier 1/2; bypassPermissions removes all tiers (dangerous, use with caution).

## §6.13 — Prompt Injection

- **Symptom**: Malicious content in files, tool outputs, or user inputs manipulates agent behavior. Can lead to data exfiltration, unauthorized operations, or system prompt leakage.
- **Evidence**: 73% of production AI deployments affected by indirect prompt injection in 2025.
- **Fix**: Input sanitization; output filtering; least-privilege tool permissions; treat all external content as untrusted.

The permission model is the primary defense against prompt injection attacks. By requiring explicit approval for destructive operations, the model ensures that even if the agent is manipulated, it cannot execute dangerous commands without human confirmation. Least-privilege tool permissions limit the blast radius of any successful injection.
