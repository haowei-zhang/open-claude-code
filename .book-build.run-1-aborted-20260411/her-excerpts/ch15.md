# HER Excerpts for Chapter 15: Search, LSP, and Code Analysis Tools

## §5 Pattern 9 — Progressive Tool Expansion

**Progressive Tool Expansion**: Start with <20 tools; activate more on demand (not all 60+ at once)

The harness does not expose all available tools to the model simultaneously. Instead:

1. **Base set**: A small set of commonly-used tools is always available
2. **Deferred tools**: Additional tools are registered but not shown in the tool list until needed
3. **On-demand activation**: When the agent encounters a situation requiring a deferred tool, it can be activated
4. **ToolSearch**: A meta-tool that allows the agent to discover and activate deferred tools

This pattern directly addresses the tool explosion problem (§6.8). By keeping the visible tool count small, the model maintains high selection accuracy. When more tools are needed, they're activated progressively rather than all at once.

## §6.8 — Tool Explosion

- **Symptom**: Too many tools degrade selection accuracy
- **Fix**: Progressive tool expansion starting with <20

When an agent has too many tools available simultaneously, it struggles to select the right one. Tool descriptions consume context window space, and the model's tool-selection accuracy degrades as the tool count increases. The HumanLayer blog notes that "too many tools is bad" -- excess tool descriptions push agents into "the dumb zone" faster.

For code analysis tools specifically (GrepTool, GlobTool, LSPTool, ToolSearchTool), progressive expansion is essential. The LSP client lifecycle is expensive to initialize and maintain. Deferring LSPTool until the agent actually needs code navigation prevents unnecessary resource consumption and context bloat.
