# HER Excerpts for Chapter 53: The 12 HER Patterns Mapped to CC

## §5 — All 12 Patterns (Concise)

### Memory and Context

1. **Persistent Instruction File** (Pattern 1): CLAUDE.md auto-loaded at session start. Deterministically injected every session. Keep under 60 lines for optimal performance. ETH Zurich study found context files can reduce success rates and increase cost by 20%+ -- minimal, targeted context is better than comprehensive dumps.

2. **Scoped Context Assembly** (Pattern 2): Multi-level instruction loading (org -> user -> project -> directory). More specific scopes override broader ones. Avoids flooding the context window with irrelevant information.

3. **Tiered Memory** (Pattern 3): Three tiers: hot (compact index, ~200 lines, always in context), warm (on-demand topic files), cold (full transcripts on disk). Balances context budget against recall.

4. **Dream Consolidation** (Pattern 4): Background processes review, deduplicate, prune memory during idle time. 8 phases, 5 compaction types. Implements Layer 8 (Learning and Adaptation) of the reference architecture.

5. **Progressive Context Compaction** (Pattern 5): Five layers escalating in aggressiveness: HISTORY_SNIP, Microcompact, CONTEXT_COLLAPSE, Autocompact, Hard Reset. Each triggered at different token thresholds.

### Workflow and Orchestration

6. **Explore-Plan-Act Loop** (Pattern 6): Three phases with escalating permissions (read-only -> discussion -> full access). Plan Mode V2 extends to five phases. Ensures agent has sufficient context before destructive actions.

7. **Context-Isolated Subagents** (Pattern 7): Separate context windows per phase; research agents cannot edit. Prevents research from consuming the main context budget. Different models for different roles.

8. **Fork-Join Parallelism** (Pattern 8): Multiple subagents in isolated git worktrees; cached parent context reuse. Enables parallel execution of independent tasks. Only results flow back to parent.

### Tools and Permissions

9. **Progressive Tool Expansion** (Pattern 9): Start with <20 tools; activate more on demand. ToolSearchTool surfaces deferred tools. Addresses tool explosion (too many tools degrade selection accuracy).

10. **Command Risk Classification** (Pattern 10): Deterministic pre-parsing and per-tool permission gating. Low/medium/high risk bands determine approval path. Does not rely on model judgment.

11. **Single-Purpose Tool Design** (Pattern 11): Each tool has one responsibility (FileReadTool, FileEditTool, GrepTool). Enables granular permission control, clear failure boundaries, targeted risk classification.

### Automation

12. **Deterministic Lifecycle Hooks** (Pattern 12): Shell commands at 25+ lifecycle points. Hook types: command, prompt, HTTP, agent, function. Exit-code semantics (0=proceed, 2=block). Composable and deterministic.
