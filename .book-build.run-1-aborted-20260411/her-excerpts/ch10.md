## §13 — Cost and Budgeting

### Cost Failure Modes

- **Infinite loops**: An agent in a retry loop can consume thousands of tokens per minute
- **Multi-agent amplification**: Generator + evaluator + sub-agents compound token costs non-linearly
- **Context window bloat**: Approaching context limits triggers expensive compaction operations or session resets
- **Model routing failures**: Expensive model used for tasks that a cheaper model could handle

### Cost-Per-Outcome Tracking

Don't just track cost-per-token. Track **cost-per-completed-task** and **cost-per-quality-unit**:
- Total cost / tasks completed = cost per task
- Total cost / test-passing features = cost per shipped feature
- Compare across harness configurations to optimize

## §9.4 — Model Routing (Opus/Sonnet/Haiku Tiers)

- **Expensive models** (Opus): Planning, orchestration, complex reasoning, evaluation
- **Mid-tier models** (Sonnet): Implementation, code generation, standard tasks
- **Cheap models** (Haiku): Summarization, output compression, simple classification

### Decision Framework for Model Routing

| Sub-task | Recommended Model Tier |
|----------|----------------------|
| Planning, architecture decisions | Expensive (Opus-class) |
| Code generation, standard implementation | Mid-tier (Sonnet-class) |
| Summarization, classification, compression | Cheap (Haiku-class) |
| Evaluation / quality judgment | Same tier as generator, or one tier higher |

The "effort" setting in cc maps directly to this tiered routing: high effort selects Opus-class reasoning, medium selects Sonnet, and fast mode may route to cheaper/faster models. Token budgets interact with model routing by enforcing cost caps that may force downgrades from expensive to cheaper models mid-session.
