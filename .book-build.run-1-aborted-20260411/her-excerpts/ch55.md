# HER Excerpts for Chapter 55: Reference Architecture: Building a Trustworthy Long-Running Agent

## §21 — Reference Architecture (8 Layers)

**IMPORTANT**: No public implementation covers all eight layers. Treat this as aspirational, not a proven blueprint.

| Layer | Name | Key Components |
|-------|------|---------------|
| 1 | Task Infrastructure | JSON task list (append-only, boolean pass/fail); task decomposition into 15-30 min sessions; priority ordering; immutable descriptions |
| 2 | Session Management | Session startup protocol; clean exit protocol; session-to-session handoff; max session duration |
| 3 | Context Engineering | Progressive compaction; observation masking (52% cost reduction); tiered memory; sub-agent isolation; context reset with structured handoff |
| 4 | Quality Gates (Back-Pressure) | Pre-commit: type-check, lint, format; Post-commit: unit/integration tests; Per-feature: E2E; Per-session: evaluator; "success is silent" |
| 5 | Safety and Security | Permission tiers; destructive operation confirmation; file protection; loop detection; rate limiting; input sanitization; idempotency keys; ACRFence |
| 6 | Cost and Observability | Per-session/task cost caps; real-time token metering; distributed tracing; structured logging; dashboard; alerting |
| 7 | Multi-Agent Coordination | Generator-Evaluator pattern; model routing; file-based communication; git conflict resolution; isolated worktrees; HITL escalation |
| 8 | Learning and Adaptation | Progress notes in files; pattern discovery to AGENTS.md; evaluator feedback; stale assumption pruning; harness versioning and A/B testing |

## §20 — 20 Best Practices (Concise Summary)

The 12 core principles (see §20) plus the session protocol, the back-pressure stack, and 8 implementation directives:

1. Context windows are the constraint; structured artifacts are the solution
2. Separate generation from evaluation (beware Ouroboros problem)
3. One task per session
4. Verify before building
5. Wire in fast feedback loops
6. Repository is single source of truth
7. Humans steer, agents execute
8. Expect eventual consistency
9. Simplify relentlessly
10. Control costs actively
11. Observe everything
12. Secure by default

Session Protocol: ORIENT -> SETUP -> VERIFY -> SELECT -> IMPLEMENT -> TEST -> UPDATE -> EXIT

Back-Pressure Stack: Type System -> Linter -> Unit Tests -> Integration Tests -> E2E/Browser Tests (only failures surface to agent)

## §19 — Decision Framework

### Choosing a Harness Approach

- Single well-defined operation? Direct prompt, no harness
- Multiple sessions? Simple harness + back-pressure
- Quality guarantees? Generator-Evaluator pattern
- Multiple concurrent agents? Full orchestration (LangGraph, etc.)

### Choosing State Management

- Single session: Context window only
- Multi-session, single agent: Three-file pattern (tasks.json + progress.txt + AGENTS.md)
- Multi-agent, shared state: File-based + git conflict resolution
- Enterprise, distributed: LangGraph + DynamoDB/Redis + event sourcing
