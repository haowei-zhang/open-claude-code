# HER Excerpts for Chapter 29: Session Persistence and Resume

## §6.16 — Checkpoint-Restore Side Effects (ACRFence)

- **Symptom**: LLM agents re-synthesize subtly different requests after restore, causing duplicate payments, unauthorized credential reuse, and irreversible side effects.
- **Evidence**: The ACRFence paper (arXiv:2603.20625) identifies two attack classes -- Action Replay and Authority Resurrection -- specific to agent checkpoint-restore.
- **Fix**: Record irreversible tool effects; enforce replay-or-fork semantics; idempotency keys for external tool calls.
- **Critical for multi-hour tasks with external side effects (API calls, payments, email sends).**

Session persistence is fundamentally a checkpoint mechanism. When a session is saved to JSONL and later resumed, the harness is performing a checkpoint-restore operation. The ACRFence findings apply directly:

- **Action Replay**: After restore, the agent may re-execute tool calls that were already completed (e.g., sending a duplicate email, making a duplicate API call)
- **Authority Resurrection**: After restore, the agent may reuse credentials or permissions that were valid at checkpoint time but have since expired or been revoked

The harness must mitigate these risks:
- Record all irreversible tool effects in the session file (not just the results, but the fact that they occurred)
- Enforce replay-or-fork semantics: on resume, either replay the exact same actions (idempotent) or fork to a new execution path
- Use idempotency keys for all external operations
- Never restore credentials from the checkpoint; always re-authenticate

## §10.3 — Session Protocol

```
1. ORIENT     -- Read workspace state (pwd, git log, progress file)
2. SETUP      -- Run init script, install dependencies if needed
3. VERIFY     -- Run baseline tests/checks (CRITICAL: before any new work)
4. SELECT     -- Pick exactly one task from the task list
5. IMPLEMENT  -- Write code with frequent git commits
6. TEST       -- Run tests, lint, type-check (automated back-pressure)
7. UPDATE     -- Update task list status, progress notes, git commit
8. EXIT       -- Clean exit with state fully persisted
```

The resume flow must follow the session protocol, starting from ORIENT. After a restore, the agent should not assume any state -- it must re-orient to the workspace, verify the current state, and then select the next task. This prevents the most common checkpoint-restore failure: continuing from a stale mental model of the workspace.
