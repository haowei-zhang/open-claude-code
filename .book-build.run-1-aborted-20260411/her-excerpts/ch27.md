# HER Excerpts for Chapter 27: Session Memory and Memory Extraction

## §5 Pattern 3 — Tiered Memory

**Tiered Memory**: Compact index (200 lines max) always in context; topic files on demand; full transcripts on disk

Memory extraction is the process that populates the warm and hot tiers of the tiered memory system. After a session (or during idle time), the harness analyzes the conversation to identify:

- **Factual discoveries**: API endpoints, configuration values, file locations
- **Behavioral patterns**: What worked, what didn't, what the user prefers
- **Contextual knowledge**: Project-specific conventions, architectural decisions
- **Error patterns**: Bugs encountered and how they were resolved

These extracted memories are then written to disk in the memdir format and indexed in the hot-tier compact index for future retrieval.

## §6.3 — Self-Evaluation Bias

- **Symptom**: Agent rates own work too generously
- **Fix**: Separate evaluator agent in a fresh context window

Self-evaluation bias directly impacts memory extraction. When the agent extracts its own memories, it tends to record successes and minimize failures. The extracted memories become an optimistically-biased record of what happened, not a truthful one. This is particularly dangerous because these biased memories persist across sessions and can mislead future work.

Mitigations for memory extraction:
- Use a separate evaluator or extraction agent (not the same agent that did the work)
- Include objective metrics in memory records (test pass/fail counts, error logs)
- Allow users to review and correct extracted memories
- Tag memories with provenance (self-extracted vs. user-verified vs. system-observed)
