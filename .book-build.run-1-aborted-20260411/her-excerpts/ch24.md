# HER Excerpts for Chapter 24: Dream Tasks: Background Consolidation

## §5 Pattern 4 — Dream Consolidation

**Dream Consolidation**: Background processes review, deduplicate, prune memory during idle time (8 phases, 5 compaction types)

Dream consolidation runs when the agent is idle, similar to how the human brain consolidates memories during sleep. The process:

1. **Review**: Scan all accumulated memories and context
2. **Deduplicate**: Identify and merge redundant information
3. **Prune**: Remove stale or irrelevant entries
4. **Reorganize**: Restructure memory indices for efficient retrieval
5. **Compact**: Apply compression to verbose entries
6. **Promote**: Elevate frequently-accessed information to the always-loaded tier
7. **Archive**: Move low-relevance entries to cold storage
8. **Index**: Update the compact index (200 lines max) for the next session

The key insight is that memory consolidation is not just compression -- it's active reorganization. The dream process doesn't just make memories smaller; it makes the most important memories more accessible and removes noise.

## §21 Layer 8 — Learning and Adaptation

### Layer 8: Learning and Adaptation
- Progress notes persisted to files (survive context resets)
- Pattern discovery logged to AGENTS.md
- Feedback from evaluator recorded for future sessions
- Stale assumptions pruned as models improve
- Harness configuration versioning and A/B testing (Meta-Harness approach)

Dream tasks implement Layer 8 of the reference architecture. They are the mechanism by which the harness learns from experience: discovering patterns in the codebase, recording feedback from tool executions, and pruning assumptions that no longer apply. The dream process is the harness's adaptation loop.
