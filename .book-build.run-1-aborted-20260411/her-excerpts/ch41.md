# HER Excerpts for Chapter 41: MCP Tools: Passthrough Permissions and Deferred Loading

## §5 Pattern 9 — Progressive Tool Expansion

**Progressive Tool Expansion**: Start with <20 tools; activate more on demand (not all 60+ at once)

The harness does not expose all available tools to the model simultaneously. Instead:

1. **Base set**: A small set of commonly-used tools is always available
2. **Deferred tools**: Additional tools are registered but not shown in the tool list until needed
3. **On-demand activation**: When the agent encounters a situation requiring a deferred tool, it can be activated
4. **ToolSearch**: A meta-tool that allows the agent to discover and activate deferred tools

MCP tools are the canonical example of deferred loading. When an MCP server connects, its tools are registered but not immediately exposed to the model. The ToolSearchTool surfaces them on demand, keeping the base tool count small while providing access to the full MCP catalog when needed.

## §6.13 — Prompt Injection via MCP Responses

- **Symptom**: Malicious content in tool outputs manipulates agent behavior. Can lead to data exfiltration, unauthorized operations, or system prompt leakage.
- **Evidence**: 73% of production AI deployments affected by indirect prompt injection in 2025.
- **Fix**: Input sanitization; output filtering; least-privilege tool permissions; treat all external content as untrusted.

MCP tool responses are a high-risk vector for indirect prompt injection. Because MCP servers run external code and return arbitrary content, a compromised or malicious server can inject instructions through its tool results. The harness must:

- Sanitize all MCP tool results before injecting them into the model context
- Strip or neutralize prompt-like patterns from MCP responses
- Treat all MCP content as untrusted input
- Validate MCP tool results against expected schemas before processing
