# HER Excerpts for Chapter 35: `useCanUseTool`: The Engine Hook

## §11.2 — Tiered Escalation

- **Tier 1** (automated): Deterministic checks handle (linting, testing, formatting)
- **Tier 2** (agent self-correction): Agent gets feedback from Tier 1 and tries again
- **Tier 3** (human front-line): Moderate-risk decisions (e.g., "should I refactor this module?")
- **Tier 4** (human expert): High-risk decisions (architecture changes, security-sensitive operations, production deployments)

The `useCanUseTool` hook implements tiered escalation for every tool call. When the agent requests to use a tool:

1. **Tier 1 check**: Does the tool match an existing permission rule? If yes, the rule determines the outcome (allow/deny/ask).
2. **Tier 2 check**: Is the tool in a risk category that allows auto-approval? The classifier provides this.
3. **Tier 3 check**: If no rule matches and the risk is moderate, present the request to the user for approval.
4. **Tier 4 check**: If the operation is high-risk (destructive, external, security-sensitive), always require explicit approval with full context.

## §11.3 — Async Approval

- Agent parks a blocked action, records context about what it tried and why it's uncertain
- Agent continues with non-blocked work
- When human approves/denies, agent resumes the blocked work path
- **Critical for multi-hour tasks**: The agent should never fully block on human input. Always have a queue of independent tasks to work on while waiting.

The hook implements async approval by parking denied or deferred tool calls and allowing the query loop to continue with other work. The agent doesn't block waiting for approval -- it records the pending decision and moves on. When the user eventually approves or denies, the hook re-evaluates the tool call and either executes it or permanently denies it.
