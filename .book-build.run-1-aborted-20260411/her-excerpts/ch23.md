# HER Excerpts for Chapter 23: Teammates and In-Process Collaboration

## §9.1 — In-Process Tier

**In-Process Subagents**: Same process, isolated context windows (e.g., Claude Code's Agent tool)
- Lowest latency, shared process resources
- Context isolation via separate context windows, not separate processes
- Best for: short, well-scoped sub-tasks (search, analysis, formatting)

Teammates are in-process sub-agents that run concurrently within the same cc instance. They share the process but maintain isolated context windows. Communication happens through message passing (SendMessageTool) rather than shared memory, ensuring clean separation.

## §11.5 — Handoff Protocols

- **Full context transfer**: Agent writes a structured handoff document summarizing current state, what's done, what's remaining, and any open questions
- **Incremental review**: Human reviews completed chunks (e.g., every 3 tasks) rather than waiting for the end
- **Checkpoint review**: Mandatory human review at 25% and 75% of task completion to catch goal misinterpretation early

For teammate collaboration, handoff protocols are essential. When one teammate needs to pass work to another, the handoff must include:
- What was accomplished (with evidence)
- What remains (with specificity)
- Any open questions or blockers
- The current state of the workspace (which files were modified, which tests pass)

Without structured handoffs, teammates duplicate work or miss dependencies. The SendMessageTool enables these handoffs by providing a structured message format that persists between teammate context windows.
