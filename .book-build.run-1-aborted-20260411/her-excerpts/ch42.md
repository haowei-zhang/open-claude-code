# HER Excerpts for Chapter 42: The Ink Renderer and Terminal Engine

## §21 — Reference Architecture UX Layer

The reference architecture does not explicitly call out a "UX layer," but the Ink renderer and terminal engine correspond to the presentation and interaction aspects of several layers:

### Layer 2: Session Management (UX aspects)
- The renderer must display session state (active task, progress, cost) clearly
- UI controls for session management (pause, resume, abort) must be accessible
- The terminal engine must handle graceful shutdown signals

### Layer 5: Safety and Security Infrastructure (UX aspects)
- Permission prompts are rendered through Ink components
- The `useCanUseTool` hook's approval UI is an Ink-rendered interactive prompt
- Destructive operation warnings must be prominent and unmissable
- The renderer must not allow the model to bypass or obscure security prompts

### Layer 6: Cost and Observability (UX aspects)
- Real-time cost display during sessions
- Token usage indicators
- Context window utilization gauges
- Alert rendering for degradation patterns

### Layer 7: Multi-Agent Coordination (UX aspects)
- Sub-agent status display
- Team message rendering
- Parallel task progress indicators

The UX layer is the human's window into the harness. A well-designed terminal UI makes the agent's behavior legible, the harness's decisions transparent, and the human's control effective. A poorly-designed UI hides critical information, making it impossible for humans to intervene before problems escalate.
