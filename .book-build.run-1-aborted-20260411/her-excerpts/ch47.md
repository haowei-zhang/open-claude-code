# HER Excerpts for Chapter 47: Cron, Schedule, Loop, and Wakeup

## §10.2 — Task Sizing Research (METR)

**Source: METR (Model Evaluation & Threat Research)**, "Measuring AI Ability to Complete Long Tasks" (March 2025):
- **AI task duration doubles every ~7 months** (capability growth). Updated Time Horizon 1.1 model (January 2026) suggests the rate has accelerated to ~4.3 months.
- **95% per-step reliability yields only 36% over 20 steps** (compound failure math)
- **Doubling task duration quadruples failure rate**

**Source: Toby Ord** (arXiv:2505.05115):
- Claude 3.7 Sonnet achieves 50% success on tasks up to 59 minutes of human-equivalent time, but requires tasks under 15 minutes for 80% success.
- **General finding**: Every AI agent in the dataset experienced degraded success rates as task duration increased, with the decline starting in the 15-60 minute range.

**Practical implication**: Right-sized tasks should target 15-30 minutes of agent work per session. Multi-hour tasks must be decomposed into many such sessions.

Cron and scheduled tasks must respect these findings. A scheduled task that runs for hours without supervision has a very low probability of success. The harness should:
- Break long-running cron tasks into short sessions (15-30 minutes each)
- Implement progress checkpoints between sessions
- Use the loop-dynamic sentinel to manage multi-session tasks
- Monitor scheduled tasks for signs of degradation (context rot, infinite loops)

## §10.1 — One-Task-Per-Session Rule

This is the single most impactful rule across all sources. It prevents:
- Context exhaustion mid-feature
- Scope creep and yak shaving
- Compounding errors
- Lost progress due to context resets

Each cron invocation should execute exactly one task. The ScheduleWakeup mechanism (which reschedules a task after a delay) implements this rule: each wake-up is a new session that picks up where the previous one left off, but it's still a single task per session.
