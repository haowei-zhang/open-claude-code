# HER Excerpts for Chapter 48: Remote Agents and CCR Integration

## §9.1 — Cloud Async Tier

**Cloud Async**: Distributed agents with message-passing (e.g., remote triggers, webhook-based coordination)
- Network-level isolation, geo-distributed possible
- Communication via APIs and message queues
- Best for: long-running tasks, cross-service coordination, scalable parallelism

Remote agents operate in the cloud async tier of multi-agent orchestration. Unlike in-process sub-agents and local orchestrators, remote agents:

1. **Run in separate infrastructure**: Different machines, possibly different regions
2. **Communicate asynchronously**: Via APIs, websockets, or message queues
3. **Persist state externally**: Session state is stored in cloud storage, not local filesystem
4. **Scale independently**: Can be provisioned and deprovisioned based on demand

CCR (Claude Code Remote) integration provides:
- **RemoteTriggerTool**: Initiates a remote agent session from the local parent
- **WebSocket sessions**: Maintain a persistent connection for real-time updates
- **Session manager**: Manages the lifecycle of remote sessions (creation, monitoring, termination)
- **Binding**: The remote agent is bound to the local parent, receiving context and returning results

## §6.16 — Checkpoint-Restore

- **Symptom**: LLM agents re-synthesize subtly different requests after restore, causing duplicate payments, unauthorized credential reuse, and irreversible side effects.
- **Evidence**: The ACRFence paper (arXiv:2603.20625) identifies two attack classes -- Action Replay and Authority Resurrection -- specific to agent checkpoint-restore.
- **Fix**: Record irreversible tool effects; enforce replay-or-fork semantics; idempotency keys for external tool calls.

Remote agents are particularly susceptible to checkpoint-restore issues because:
- Network interruptions can cause session drops and restores
- The remote session may be checkpointed and restored on different infrastructure
- The local parent may issue the same trigger twice (due to network retry)
- The remote agent may re-execute operations after a reconnect

The harness must implement idempotency for remote triggers: each trigger must have a unique ID, and the remote agent must check whether it has already processed a trigger before executing it.
