# HER Excerpts for Chapter 09: System Prompts and Prompt Assembly

## §7.1 — Persistent Instruction File

CLAUDE.md / AGENTS.md / .cursor/rules Files:
- Deterministically injected into system prompt every session
- Keep under 60 lines for optimal performance

Three-part structure recommended (if used): WHY (project context) / WHAT (conventions) / HOW (workflows)

## §5 Pattern 2 — Scoped Context Assembly

**Scoped Context Assembly**: Multi-level instruction loading (org -> user -> project -> directory)

This pattern loads instructions at multiple scope levels, with more specific scopes overriding or supplementing broader ones:
- **Org level**: Organization-wide policies and conventions
- **User level**: Individual developer preferences and workflows
- **Project level**: Project-specific rules, tech stack, architecture
- **Directory level**: Context-sensitive rules for specific subdirectories

The key insight is that not all context is relevant all the time. By scoping instructions to the relevant level, the harness avoids flooding the context window with irrelevant information while ensuring the most pertinent instructions are always present.

## §7.1 — ETH Zurich AGENTS.md Finding

**ETH Zurich study** (arXiv:2602.11988, "Evaluating AGENTS.md"): This paper found that **context files tend to reduce task success rates compared to providing no repository context, while also increasing inference cost by over 20%.** This applies to both LLM-generated and developer-committed context files. The paper recommends describing only "minimal requirements" -- verbose instructions and detailed directory trees hurt rather than help.

**Implication**: More instruction is not always better. The harness should provide minimal, targeted context rather than comprehensive documentation dumps. This finding challenges the common assumption that detailed AGENTS.md files improve agent performance.
