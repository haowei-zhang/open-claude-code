# HER Excerpts for Chapter 25: Messages and the Conversation Model

## §5 Pattern 5 — Progressive Context Compaction

**Progressive Context Compaction**: Four layers: HISTORY_SNIP, Microcompact, CONTEXT_COLLAPSE, Autocompact

As the conversation grows, the harness progressively compacts older context to keep the working window manageable. The four layers activate at increasing token thresholds, each more aggressive than the last:

1. **HISTORY_SNIP**: Lightweight -- marks old tool outputs as summarized
2. **Microcompact**: Compresses individual tool results into concise summaries
3. **CONTEXT_COLLAPSE**: Aggressive -- replaces entire conversation segments with summaries
4. **Autocompact**: Full reset -- clears context and starts fresh with a structured handoff

The message model directly implements this pattern. Each message type (user, assistant, tool_result) has different compaction semantics. Tool results are compacted first (they're verbose and often redundant), followed by older assistant turns, followed by user messages. The compaction boundary markers (`<history_snip>`) are embedded in the message stream to signal where context has been summarized.

## §6.1 — Context Rot

- **Symptom**: Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.
- **Fix**: Active context management (summarization, pruning, progress file pattern)

The message model is the primary defense against context rot. By structuring messages with explicit types, attachments, and compaction boundaries, the harness can identify which content is most important to preserve and which can be safely summarized or discarded. The `<history_snip>` markers serve as checkpoints: if the agent's behavior degrades after a compaction boundary, the harness knows that critical context was lost during that compaction pass.
