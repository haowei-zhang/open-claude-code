# HER Excerpts for Chapter 57: Closing: Lessons for the Harness Engineering Discipline

## §18 — Limitations

### Is This Just DevOps Rebranded? (§18.1)
Harness engineering IS substantially DevOps applied to a new workload type. The core innovation is the *probabilistic* nature of the workload -- DevOps orchestrates deterministic processes, while harness engineering orchestrates a non-deterministic process (the LLM) that requires fundamentally different error handling (retry-and-hope rather than fix-the-bug).

### The Ouroboros Problem (§18.2)
When both generator and evaluator are LLMs, who validates the validator? The NLAH paper's verifier ablation (-0.8% on SWE-bench) shows this is not theoretical. The strongest evaluators are deterministic (tests, linters, type checkers).

### The "Stone Soup" Attribution Problem (§18.3)
Massive human labor gets misattributed to AI capability. Huntley's caveat -- "There is no way this is possible without senior expertise guiding Ralph" -- is the honest version.

### Limited Applicability Beyond Coding (§18.4)
Coding has the deterministic-probabilistic pairing (write code, run compiler/tests). Most activities lack this structure. Patterns should not be assumed to generalize.

### Greenfield Bias (§18.5)
Huntley: "There's no way in heck would I use Ralph in an existing code base." Many impressive results are greenfield. Brownfield is significantly harder.

### When NOT to Use (§18.6)
- Simple one-shot tasks
- Domains without deterministic verification
- When human review is faster
- Security-critical operations without proper isolation
- Low-harnessability codebases

### The Scale Confusion (§18.7)
Ralph (~10 lines) vs. Generator-Evaluator (~100s of lines) vs. Full orchestration (~1000s of lines) vs. 8-layer architecture (aspirational). These are qualitatively different systems, not points on a continuum.

## §10.2 — METR Task Sizing Research

- **AI task duration doubles every ~7 months** (accelerating to ~4.3 months per Time Horizon 1.1)
- **95% per-step reliability yields only 36% over 20 steps** (compound failure math)
- **Doubling task duration quadruples failure rate**
- Claude 3.7 Sonnet: 50% success at 59 min, 80% success requires tasks under 15 min
- Right-sized tasks: 15-30 minutes per session; multi-hour tasks decomposed into many sessions

## §15 — Academic Research

### NLAH (Natural-Language Agent Harnesses) (§15.1)
Externalizes harness control as portable natural-language artifacts. Key ablation results: self-evolution +4.8% (SWE-bench), file-backed state +1.6%, verifier **-0.8%**, multi-candidate search **-2.4%**. Cautionary finding: more structure doesn't automatically improve performance when intermediate criteria diverge from final benchmarks.

### Meta-Harness (§15.2)
Outer-loop system that searches over harness code. Results: +7.7 points over SOTA context management with 4x fewer tokens; +4.7 points on 200 IMO-level problems. Demonstrates harness configurations can be systematically optimized rather than hand-tuned.

### AutoHarness (§15.3)
LLMs automatically generate constraint-enforcement harnesses. Smaller model + synthesized harness outperformed larger model without one. Harness *prevents* illegal moves (proactive constraint enforcement) rather than eliminating them retroactively.

### ACRFence (§15.6)
Identifies checkpoint-restore threat model: Action Replay (replaying completed actions) and Authority Resurrection (reusing expired credentials). Solution: record irreversible tool effects, enforce replay-or-fork semantics. Directly relevant to multi-hour harness systems that need checkpointing and recovery.
