# HER Excerpts for Chapter 31: CLAUDE.md, Settings Cascade, and Managed Settings

## §7.1 — CLAUDE.md / AGENTS.md

CLAUDE.md / AGENTS.md / .cursor/rules Files:
- Deterministically injected into system prompt every session
- Keep under 60 lines for optimal performance

- **ETH Zurich study** (arXiv:2602.11988, "Evaluating AGENTS.md"): This paper found that **context files tend to reduce task success rates compared to providing no repository context, while also increasing inference cost by over 20%.** This applies to both LLM-generated and developer-committed context files. The paper recommends describing only "minimal requirements" -- verbose instructions and detailed directory trees hurt rather than help.

- Three-part structure recommended (if used): WHY (project context) / WHAT (conventions) / HOW (workflows)

## §7 — Six Configuration Surfaces

Six configuration surfaces compose a modern harness:

### 7.1 CLAUDE.md / AGENTS.md / .cursor/rules Files
- Deterministically injected into system prompt every session
- Keep under 60 lines for optimal performance

### 7.2 MCP Servers
- Extend capabilities with external tool access
- "Too many tools is bad" -- excess tool descriptions push agents into "the dumb zone" faster
- If an MCP server duplicates CLI functionality well-represented in training data, use the CLI instead
- **Security note**: MCP servers are a supply chain attack surface. Treat them like untrusted npm packages.

### 7.3 Skills (Progressive Disclosure)
- Agents access specific instructions/tools only when contextually needed
- Treat skills like untrusted npm packages (security risk)
- Reduces cognitive load by not front-loading all instructions

### 7.4 Sub-Agents (Context Firewalls)
- Discrete tasks in isolated context windows
- Use expensive models (Opus) for parent orchestration
- Use cheaper models (Sonnet, Haiku) for sub-tasks
- Primary benefit: prevents research/exploration from consuming the main context window

### 7.5 Hooks (Lifecycle Events)
- User-defined commands at lifecycle events (PreToolUse, PostToolUse, Stop, etc.)

### 7.6 Back-Pressure Mechanisms
- "Swallow the output and only surface errors"
- Success is silent; only failures produce verbose output

The settings cascade maps directly to these surfaces: org settings, user settings, project settings, directory settings, environment variables, and command-line flags each contribute to the configuration of one or more surfaces. The cascade determines precedence when multiple sources conflict.
