# HER Excerpts for Chapter 45: Plan Mode V2: The Five-Phase Model

## §5 Pattern 6 — Explore-Plan-Act Loop

**Explore-Plan-Act Loop**: Three phases with escalating permissions (read-only -> discussion -> full access)

This pattern structures the agent's core execution loop into three distinct phases:
1. **Explore**: Read-only access. Agent gathers information, reads files, searches code. No mutations permitted.
2. **Plan**: Discussion mode. Agent proposes changes, discusses approach with user. Still no writes.
3. **Act**: Full access. Agent implements the plan, writes files, runs commands.

Plan Mode V2 extends this three-phase model into five phases:
- Additional intermediate phases for parallel exploration and plan refinement
- Gating of specific tool categories by phase (read-only tools in explore, write tools only in act)
- User-visible phase transitions that require explicit confirmation

The escalating permissions ensure the agent has sufficient context before taking destructive actions. The five-phase model provides finer-grained control than the three-phase model, particularly for complex tasks that benefit from parallel exploration before committing to a plan.

## §10.3 — Session Protocol

```
1. ORIENT     -- Read workspace state (pwd, git log, progress file)
2. SETUP      -- Run init script, install dependencies if needed
3. VERIFY     -- Run baseline tests/checks (CRITICAL: before any new work)
4. SELECT     -- Pick exactly one task from the task list
5. IMPLEMENT  -- Write code with frequent git commits
6. TEST       -- Run tests, lint, type-check (automated back-pressure)
7. UPDATE     -- Update task list status, progress notes, git commit
8. EXIT       -- Clean exit with state fully persisted
```

Plan Mode maps to the session protocol: the Explore phase corresponds to ORIENT + VERIFY, the Plan phase corresponds to SELECT, and the Act phase corresponds to IMPLEMENT + TEST + UPDATE. The five-phase model inserts additional verification and refinement steps between these high-level stages.
