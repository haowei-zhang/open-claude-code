# HER Excerpts for Chapter 18: The Agent Tool: Entry, Inputs, and Lifecycle

## §7.4 — Sub-Agents as a Configuration Surface

Sub-Agents (Context Firewalls):
- Discrete tasks in isolated context windows
- Use expensive models (Opus) for parent orchestration
- Use cheaper models (Sonnet, Haiku) for sub-tasks
- Primary benefit: prevents research/exploration from consuming the main context window

The Agent Tool's inputs -- description, prompt, subagent_type, model, run_in_background, team_name, mode, isolation, cwd -- constitute a rich configuration surface. Each parameter controls a different aspect of sub-agent behavior:

- **model**: Directly maps to the tiered model routing pattern (§9.4)
- **isolation**: Controls whether the sub-agent shares the parent's context or runs in isolation
- **run_in_background**: Enables async approval patterns (§11.3)
- **team_name**: Configures multi-agent coordination (§9.1)

## §5 Pattern 7 — Context-Isolated Subagents

**Context-Isolated Subagents**: Separate context windows per phase; research agents cannot edit

Each sub-agent operates in its own context window, completely isolated from the parent. This ensures that:

- Research and exploration don't consume the parent's context budget
- A sub-agent's failure doesn't corrupt the parent's state
- Different sub-agents can use different models (expensive for planning, cheap for execution)
- The parent retains full control over what information flows back from sub-agents

The key constraint: research agents cannot edit files. This enforces the principle that information gathering and action taking are separate responsibilities.

## §5 Pattern 8 — Fork-Join Parallelism

**Fork-Join Parallelism**: Multiple subagents in isolated git worktrees; cached parent context reuse

The fork-join pattern enables parallel execution of independent tasks:

1. **Fork**: The parent agent spawns multiple sub-agents, each in its own isolated worktree with a cached copy of the parent's context
2. **Execute**: Sub-agents work in parallel on independent tasks without interfering with each other
3. **Join**: Results from all sub-agents are merged back into the parent's context

Key design decisions:
- Git worktrees provide filesystem isolation
- Parent context is cached and shared (not re-constructed for each sub-agent)
- Only results (not intermediate context) flow back to the parent
- The parent orchestrates the join, resolving any conflicts
