# HER Excerpts for Chapter 14: The Bash Tool, Classifiers, and Sandboxing

## §5 Pattern 10 — Command Risk Classification

**Command Risk Classification**: Deterministic pre-parsing and per-tool permission gating

Before any command reaches the model, the harness classifies it by risk level using deterministic rules. This pre-parsing ensures that:

- **Destructive commands** (rm -rf, git push --force, DROP TABLE) require explicit user approval
- **Safe commands** (ls, cat, git status) can proceed automatically
- **Ambiguous commands** fall into a middle tier that may require contextual evaluation

The classification is deterministic -- it does not rely on the model's judgment. This is critical because a model under prompt injection could be coaxed into classifying a dangerous command as safe. The classifier uses pattern matching, allowlists, and denylists to make fast, reliable risk assessments.

## §6.16 — Checkpoint-Restore Side Effects (ACRFence)

- **Symptom**: LLM agents re-synthesize subtly different requests after restore, causing duplicate payments, unauthorized credential reuse, and irreversible side effects.
- **Evidence**: The ACRFence paper (arXiv:2603.20625) identifies two attack classes -- Action Replay and Authority Resurrection -- specific to agent checkpoint-restore.
- **Fix**: Record irreversible tool effects; enforce replay-or-fork semantics; idempotency keys for external tool calls.
- **Critical for multi-hour tasks with external side effects (API calls, payments, email sends).**

For the Bash tool specifically, checkpoint-restore side effects are a direct concern. A Bash command that sends an email, makes a payment, or deploys a service is irreversible. If the session is restored from a checkpoint, the agent may re-execute the same command, causing duplicate operations. The harness must track which Bash commands have been executed with irreversible side effects and prevent re-execution after restore.

## §12.4 — Security Threat Model

**Indirect Prompt Injection**: Malicious instructions embedded in files, tool outputs, web pages, or database records that the agent processes. The agent follows these injected instructions because it cannot reliably distinguish them from legitimate context.
- **Mitigation**: Input sanitization on all external content; treat file contents and tool outputs as untrusted; use deterministic validation (not LLM judgment) for security-critical decisions.

**Data Exfiltration Through Tool Calls**: Agent sends sensitive data to external services via tool calls (API requests, file uploads, etc.).
- **Mitigation**: Allowlist external endpoints; monitor tool call parameters for sensitive data patterns; require human approval for external communications.
