# HER Excerpts for Chapter 26: Memdir: Tiered Memory on Disk

## §5 Pattern 3 — Tiered Memory

**Tiered Memory**: Compact index (200 lines max) always in context; topic files on demand; full transcripts on disk

Memory is organized in three tiers by access speed and cost:

1. **Hot tier** (always in context): A compact index, capped at ~200 lines, that lists available memories with brief descriptions. This index is loaded into every query, giving the model awareness of what it knows without consuming excessive context.

2. **Warm tier** (on-demand files): Individual memory files stored on disk, loaded only when the model requests them via memory retrieval. Each file covers a specific topic or context.

3. **Cold tier** (full transcripts): Complete session transcripts and raw data, stored on disk and rarely accessed. These serve as the authoritative record but are too large to load into context.

The tiered approach balances context budget against recall: the hot tier provides breadth (awareness of all memories), the warm tier provides depth (detailed information when needed), and the cold tier provides completeness (full history for auditing or recovery).

## §7.1 — Persistent Instruction File

CLAUDE.md / AGENTS.md / .cursor/rules Files:
- Deterministically injected into system prompt every session
- Keep under 60 lines for optimal performance
- Three-part structure recommended (if used): WHY (project context) / WHAT (conventions) / HOW (workflows)

The memdir system extends the persistent instruction file pattern. While CLAUDE.md provides project-level instructions that persist across sessions, memdir provides session-level memories that persist across context resets. Both patterns solve the same fundamental problem: ensuring critical information survives beyond the ephemeral context window.
