# Part VIII: Long-Running Work

An agent that can execute a single query and return a result is a demonstration. An agent that can sustain work across hours, coordinate parallel efforts on separate branches, wake itself on a schedule, and delegate tasks to remote compute—that is a production system. Part VIII examines the mechanisms cc uses to transform a stateless question-answering loop into a durable, long-running worker.

The chapters in this part share a common concern: extending the agent's reach beyond the boundaries of a single interactive session. A harness that exits when the terminal closes is useful but brittle. The features explored here—plan mode, worktrees, cron scheduling, remote agents, and proactive assistance—all answer the question of how an agent persists, coordinates, and stays relevant when the human operator steps away or when the scope of work exceeds what one loop iteration can accomplish.

These chapters belong together because each one introduces a new axis of temporal or spatial extension. Plan Mode V2 (Chapter 45) extends the agent temporally by splitting a task into a read-only exploration phase and a gated execution phase, reducing the risk of premature action on complex tasks. Worktrees (Chapter 46) extend the agent spatially by allowing parallel branches of filesystem work to proceed in isolation, preventing conflicts between concurrent efforts. Cron and scheduling (Chapter 47) extend the agent temporally in a different direction, enabling it to wake itself at intervals and perform recurring work without human initiation. Remote agents (Chapter 48) extend the agent spatially again, this time across machine boundaries, delegating work to cloud-hosted instances that can outlive the local process. The KAIROS assistant and Buddy layer (Chapter 49) extend the agent's relationship with the user, introducing proactive affordances and experimental features that make long-running interaction feel less like a tool invocation and more like a collaboration.

Each of these features pushes against the core constraint of the query loop: it was designed for request-response, not for persistence. The result is a set of architectural patterns—fork-join parallelism, sentinel-based looping, websocket session binding, feature-gated experiment layers—that any harness engineer will need when moving from a prototype to a deployable system.

Chapter 45, Plan Mode V2: The Five-Phase Model, dissects cc's structured planning workflow, its parallel exploration agents, read-only enforcement during the planning phase, and the gated transition to execution. Chapter 46, Worktrees: Isolated Parallel Branches, covers git worktree creation and management, symlinked dependencies, lifecycle hooks, and the safety guarantees that isolated filesystem branches provide. Chapter 47, Cron, Schedule, Loop, and Wakeup, examines scheduled task storage, dynamic loop sentinels, per-project limits, and the monitor tool that observes recurring work. Chapter 48, Remote Agents and CCR Integration, details the remote trigger tool, websocket-based session management, and the binding between a local parent session and its cloud-hosted counterpart. Chapter 49, KAIROS Assistant, Buddy, and Experimental Layers, surveys the proactive assistant mode, the Buddy companion feature, and the feature-gated experiments that test new UX affordances before broader release.

By the end of this part, the reader should understand how cc crosses the boundary from interactive tool to autonomous worker. The architectural patterns here—phased execution, filesystem isolation, scheduled invocation, remote delegation, and proactive affordance—form the substrate on which any trustworthy long-running agent must be built. A harness that cannot persist, coordinate, or self-schedule remains fragile; the chapters that follow show how cc addresses each of these requirements.
