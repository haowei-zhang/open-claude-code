## 14. Observability and Monitoring

Per LangChain's State of Agent Engineering survey (1,340 respondents, Nov-Dec 2025), **89% of organizations with production agents have implemented observability** (94% among those with agents in production). 62% have detailed per-step tracing. This is table stakes, not optional.

### 14.1 Three Pillars for Agent Observability

1. **Traces**: Distributed tracing across multi-agent workflows. Each tool call, sub-agent dispatch, and model invocation is a span. OpenTelemetry semantic conventions for AI agent traces are emerging.

2. **Metrics**: Per-session and per-task metrics:
   - Token usage (input/output, per model)
   - Cost accrual rate
   - Tool call latency and success rates
   - Task completion rate and time-to-completion
   - Context window utilization (% of max)

3. **Logs**: Structured logging of agent decisions, tool call parameters/results, and state transitions. Critical for post-hoc debugging of "why did the agent do X?"

### 14.2 The Observability Gap

Agents fail silently because their response format looks correct. A 200 OK from a tool call doesn't mean the operation succeeded semantically. Observability must go beyond "did the API call return?" to "did the operation achieve its intended effect?"

### 14.3 Multi-Hour Session Dashboard

For multi-hour tasks, the operator needs visibility into:
- **Progress**: How many tasks completed vs. remaining?
- **Health**: Is the agent making progress or stuck in a loop?
- **Cost**: Cumulative spend and spend rate
- **Context**: How full is the context window? When was the last reset?
- **Quality**: Evaluator scores over time -- are they trending down?
- **Alerts**: Degradation pattern detection (context rot, loop detection, cost anomaly)

### 14.4 Alerting Patterns

- **Loop detection**: Same tool called with same parameters N times in M minutes
- **Context rot signal**: Agent re-solves a problem it already solved (detected via semantic similarity of tool calls)
- **Cost spike**: Spend rate exceeds 2x the rolling average
- **Quality degradation**: Evaluator scores drop below threshold for N consecutive evaluations
- **Staleness**: No progress file update or git commit for N minutes

## 13. Cost Management and Budgeting

**This section addresses the most conspicuous gap in the original harness engineering literature.** Per CIO research, enterprise budgets underestimate AI agent TCO by 40-60%. For multi-hour tasks, uncontrolled cost is the #1 operational risk.

### 13.1 Cost Failure Modes

- **Infinite loops**: An agent in a retry loop can consume thousands of tokens per minute
- **Multi-agent amplification**: Generator + evaluator + sub-agents compound token costs non-linearly
- **Context window bloat**: Approaching context limits triggers expensive compaction operations or session resets
- **Model routing failures**: Expensive model used for tasks that a cheaper model could handle

### 13.2 Cost Control Architecture

```
Per-task cost cap         -- Hard limit; task fails gracefully if exceeded
Per-session cost cap      -- Prevents runaway sessions
Per-hour spend rate alert -- Anomaly detection on spend velocity
Dead-letter queue         -- Tasks exceeding thresholds get queued for human review
Budget allocation         -- Separate budgets for generator/evaluator/sub-agents
```

### 13.3 Cost Optimization Strategies

1. **Semantic routing**: Route simple sub-tasks (summarization, classification) to cheap models (Haiku); reserve expensive models (Opus) for planning and complex reasoning
2. **Observation masking**: 52% cost reduction by hiding irrelevant tool outputs (JetBrains Research, verified)
3. **Sub-agent isolation**: Research in cheap-model sub-agents rather than expensive parent context
4. **Early termination**: Kill sessions that are clearly stuck (loop detection, no-progress-for-N-minutes)
5. **Token metering**: Real-time tracking of input/output tokens per session, per task, per agent

### 13.4 Cost-Per-Outcome Tracking

Don't just track cost-per-token. Track **cost-per-completed-task** and **cost-per-quality-unit**:
- Total cost / tasks completed = cost per task
- Total cost / test-passing features = cost per shipped feature
- Compare across harness configurations to optimize
