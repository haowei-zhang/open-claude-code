## 11. Human-in-the-Loop Design Patterns

The canonical sources state "Humans steer, agents execute" but rarely detail the specific patterns for how humans participate in agent workflows. For multi-hour tasks, these patterns are essential.

### 11.1 Confidence-Based Routing
- **Above threshold** (e.g., 90% confidence): Agent proceeds autonomously
- **Below threshold**: Agent queues the decision for human approval, continues with other work

### 11.2 Tiered Escalation
- **Tier 1** (automated): Deterministic checks handle (linting, testing, formatting)
- **Tier 2** (agent self-correction): Agent gets feedback from Tier 1 and tries again
- **Tier 3** (human front-line): Moderate-risk decisions
- **Tier 4** (human expert): High-risk decisions (architecture, security, production)

### 11.3 Async Approval
- Agent parks a blocked action, records context, continues with non-blocked work
- **Critical for multi-hour tasks**: The agent should never fully block on human input.

### 11.4 Context-Rich Escalation
When the agent escalates to a human, it must provide: what it was trying to do, what it tried, why it failed, what options it sees, what it recommends.

### 11.5 Handoff Protocols
- **Full context transfer**: Structured handoff document
- **Incremental review**: Human reviews completed chunks
- **Checkpoint review**: Mandatory human review at 25% and 75% completion

## 13. Cost Management and Budgeting

**This section addresses the most conspicuous gap in the original harness engineering literature.** Per CIO research, enterprise budgets underestimate AI agent TCO by 40-60%.

### 13.1 Cost Failure Modes
- **Infinite loops**: Thousands of tokens per minute
- **Multi-agent amplification**: Generator + evaluator + sub-agents compound non-linearly
- **Context window bloat**: Expensive compaction operations
- **Model routing failures**: Expensive model for cheap-model tasks

### 13.2 Cost Control Architecture
```
Per-task cost cap         -- Hard limit; task fails gracefully if exceeded
Per-session cost cap      -- Prevents runaway sessions
Per-hour spend rate alert -- Anomaly detection on spend velocity
Dead-letter queue         -- Tasks exceeding thresholds get queued for human review
Budget allocation         -- Separate budgets for generator/evaluator/sub-agents
```

### 13.3 Cost Optimization Strategies
1. **Semantic routing**: Cheap models for simple tasks, expensive for planning
2. **Observation masking**: 52% cost reduction (JetBrains Research, verified)
3. **Sub-agent isolation**: Research in cheap-model sub-agents
4. **Early termination**: Kill stuck sessions
5. **Token metering**: Real-time tracking per session/task/agent

### 13.4 Cost-Per-Outcome Tracking
Track **cost-per-completed-task** and **cost-per-quality-unit**, not just cost-per-token.

## 14. Observability and Monitoring

89% of organizations with production agents have implemented observability. This is table stakes, not optional.

### 14.1 Three Pillars
1. **Traces**: Distributed tracing across multi-agent workflows (OpenTelemetry)
2. **Metrics**: Token usage, cost accrual, tool call latency, task completion, context utilization
3. **Logs**: Structured logging of agent decisions, tool call parameters/results, state transitions

### 14.2 The Observability Gap
Agents fail silently because their response format looks correct. A 200 OK doesn't mean the operation succeeded semantically.

### 14.3 Multi-Hour Session Dashboard
Progress, Health, Cost, Context, Quality, Alerts.

### 14.4 Alerting Patterns
Loop detection, context rot signal, cost spike, quality degradation, staleness.

## 20. Synthesized Best Practices

### The 12 Core Principles

1. Context windows are the constraint; structured artifacts are the solution.
2. Separate generation from evaluation.
3. One task per session.
4. Verify before building.
5. Wire in fast feedback loops.
6. Repository is single source of truth.
7. Humans steer, agents execute.
8. Expect eventual consistency.
9. Simplify relentlessly.
10. Control costs actively.
11. Observe everything.
12. Secure by default.

### The Session Protocol (Universal)
```
ORIENT  -> SETUP -> VERIFY -> SELECT -> IMPLEMENT -> TEST -> UPDATE -> EXIT
```

### The Back-Pressure Stack
```
Type System -> Linter -> Unit Tests -> Integration Tests -> E2E/Browser Tests
     ^                                                            |
     +---- Only failures surface to agent context ----------------+
```
