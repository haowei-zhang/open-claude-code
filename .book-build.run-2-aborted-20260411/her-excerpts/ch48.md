### 9.1 Three Tiers

1. **In-Process Subagents**: Same process, isolated context windows (e.g., Claude Code's Agent tool)
2. **Local Orchestrators**: Separate processes coordinated by a parent (e.g., Ralph loop spawning multiple Claude instances)
3. **Cloud Async**: Distributed agents with message-passing (e.g., remote triggers, webhook-based coordination)

(From Section 9 Multi-Agent Orchestration)

The cloud async tier is the most operationally complex:
- Agents run on distributed infrastructure with message-passing coordination
- Remote triggers and webhook-based coordination replace local process management
- Each distributed agent has its own context, tools, and permissions
- From Section 9.3: File-based communication is preferred; git provides audit trail and rollback
- From Section 9.4 Model Routing: Expensive models for planning/orchestration, cheap models for execution

### 6.16 Checkpoint-Restore Side Effects
- **Symptom**: LLM agents re-synthesize subtly different requests after restore, causing duplicate payments, unauthorized credential reuse, and irreversible side effects.
- **Evidence**: The ACRFence paper (arXiv:2603.20625) identifies two attack classes -- Action Replay and Authority Resurrection -- specific to agent checkpoint-restore.
- **Fix**: Record irreversible tool effects; enforce replay-or-fork semantics; idempotency keys for external tool calls (see Section 12.6).
- **Critical for multi-hour tasks with external side effects (API calls, payments, email sends).**

From Section 12.6 Idempotency for External Operations:
- Generate a unique operation ID before each external call
- Check whether the operation has already been performed before executing
- Store operation results mapped to their IDs
- On retry or restore, check the ID first -- if already completed, return the stored result

From Section 15.6 ACRFence: Checkpoint-Restore Security:
- Identifies a novel threat model for LLM agent checkpoint-restore
- Two attack classes: Action Replay (replaying completed actions) and Authority Resurrection (reusing expired credentials)
- Proposed solution: ACRFence records irreversible tool effects and enforces replay-or-fork semantics
- **Directly relevant to multi-hour harness systems** that need checkpointing and recovery
