# HER Excerpt for Chapter 27

## From §5: Pattern 3 Tiered Memory

3. **Tiered Memory**: Compact index (200 lines max) always in context; topic files on demand; full transcripts on disk

This pattern implements a three-tier memory architecture inspired by CPU caching:

**Tier 1 -- Always-loaded index**: A compact index (200 lines maximum) that is always present in the context window. This index contains pointers to detailed information stored elsewhere. It provides the agent with a map of what it knows without consuming excessive context space.

**Tier 2 -- On-demand topic files**: Detailed information organized by topic, loaded into context only when needed. When the agent needs information about a specific topic, it reads the corresponding topic file. This keeps the context window focused on the current task while ensuring detailed information is available when required.

**Tier 3 -- Full transcripts on disk**: Complete conversation histories and detailed logs stored on disk but not loaded into context. These serve as an audit trail and can be searched when needed, but they do not consume context window space.

## From §6.3: Self-Evaluation Bias

- **Symptom**: Agent rates own work too generously
- **Fix**: Separate evaluator agent in a fresh context window

Self-evaluation bias is one of the most consistently identified failure modes across all sources. As Anthropic's research states: Agents "confidently praise their own work even when quality is mediocre." This bias is not a minor issue -- it fundamentally undermines the agent's ability to assess whether it has completed a task correctly.

The fix is structural: separate the generator from the evaluator. The evaluator agent operates in a fresh context window with no knowledge of the generation process. It evaluates the output on its own merits, using specific gradable criteria with clear definitions. This structural separation eliminates the bias that comes from the generator having invested effort in producing the output.

However, this fix introduces the Ouroboros Problem (Section 9.2): when both generator and evaluator are LLMs, who validates the validator? The NLAH paper's ablation data shows that adding a verifier can actually hurt performance (-0.8% on SWE-bench). The strongest evaluators are deterministic (tests, linters, type checkers) -- use LLM evaluation only for judgments that deterministic tools cannot make.
