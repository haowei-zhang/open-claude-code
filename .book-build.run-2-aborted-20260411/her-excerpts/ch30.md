## From §21: Layer 2 Session Management

### Layer 2: Session Management
- Session startup protocol (orient -> setup -> verify -> select)
- Clean exit protocol (update state -> commit -> persist notes)
- Session-to-session handoff via structured files
- Maximum session duration limits with graceful wind-down

Layer 2 defines the lifecycle of individual agent sessions. The session startup protocol ensures that every session begins with a consistent orientation to the current workspace state, preventing the agent from operating on stale assumptions. The clean exit protocol ensures that state is fully persisted before the session ends, preventing data loss on session termination.

**Session-to-session handoff** is the critical mechanism for multi-hour tasks. Since no single session can complete a multi-hour task, the handoff must capture all essential state: what was done, what remains, what decisions were made, and what the agent was working on when the session ended. This handoff is implemented via structured files (the Three-File State Pattern from Section 8.2) rather than in-memory state, because in-memory state is lost when the session ends.

**Maximum session duration limits** prevent context rot and context anxiety by ensuring that sessions don't run long enough for degradation to become significant. When a session approaches its duration limit, the graceful wind-down protocol ensures that the agent completes its current task, updates state, and exits cleanly rather than being abruptly terminated or continuing to work in a degraded state.
