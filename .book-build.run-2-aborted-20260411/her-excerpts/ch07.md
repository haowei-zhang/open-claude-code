# HER Excerpt for Chapter 7

## From §5: Pattern 6 "Explore-Plan-Act Loop"

6. **Explore-Plan-Act Loop**: Three phases with escalating permissions (read-only -> discussion -> full access)

This pattern structures agent work into three distinct phases:

1. **Explore**: Read-only access. The agent surveys the codebase, understands the current state, and gathers information. No modifications permitted. This prevents premature action and ensures the agent has sufficient context before making changes.

2. **Plan**: Discussion mode. The agent formulates a plan, discusses approaches, and gets alignment on strategy. The agent can propose changes but not execute them. This creates a natural checkpoint for human review before implementation begins.

3. **Act**: Full access. The agent executes the plan with write permissions, makes code changes, runs tests, and completes the task.

**Key benefit**: The escalating permissions prevent the most common failure mode of agents jumping to implementation before understanding the problem. The Explore phase forces information gathering; the Plan phase forces explicit reasoning about approach; the Act phase only begins after both are complete.

## From §6.1: Context Rot

- **Symptom**: Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.
- **Fix**: Active context management (summarization, pruning, progress file pattern)

Context rot is one of the most insidious failure modes because it is gradual and often goes unnoticed until significant degradation has occurred. The agent doesn't suddenly fail -- it slowly becomes less coherent, re-visiting decisions it already made, contradicting earlier conclusions, or losing track of the original task goal.

The "mid-window" position is critical: research shows that information at the beginning and end of a context window is more reliably attended to, while information in the middle degrades fastest. This means that as a context window fills, early instructions and later observations are retained, but the reasoning chain in the middle can be lost.

## From §6.2: Premature Completion

- **Symptom**: Agent declares work done too early
- **Fix**: Comprehensive JSON feature list with all items initially marked "failing"

The agent optimistically declares success because it has completed the *obvious* parts of the task while missing edge cases, error handling, or secondary requirements. The JSON feature list approach forces the agent to confront a comprehensive list of requirements, each with a boolean pass/fail status, preventing the agent from declaring victory when half the work remains undone.

## From §6.7: Infinite Loops

- **Symptom**: Retry without progress
- **Fix**: Maximum retry counts, exponential backoff, loop detection

The agent enters a cycle where it attempts the same operation repeatedly, each time receiving the same error or producing the same incorrect result. Without intervention, the agent will continue cycling until context exhaustion or cost limits are reached. Detection mechanisms include: counting consecutive identical tool calls, tracking whether the agent's output changes between attempts, and monitoring whether progress file updates are occurring.
