# HER Excerpt for Chapter 8

## From §13: Cost Management and Budgeting -- Observation Masking

**This section addresses the most conspicuous gap in the original harness engineering literature.** Per CIO research, enterprise budgets underestimate AI agent TCO by 40-60%. For multi-hour tasks, uncontrolled cost is the #1 operational risk.

### 13.3 Cost Optimization Strategies

1. **Semantic routing**: Route simple sub-tasks (summarization, classification) to cheap models (Haiku); reserve expensive models (Opus) for planning and complex reasoning
2. **Observation masking**: 52% cost reduction by hiding irrelevant tool outputs (JetBrains Research, verified)
3. **Sub-agent isolation**: Research in cheap-model sub-agents rather than expensive parent context
4. **Early termination**: Kill sessions that are clearly stuck (loop detection, no-progress-for-N-minutes)
5. **Token metering**: Real-time tracking of input/output tokens per session, per task, per agent

**Observation masking** is the single most effective cost optimization with verified evidence. The principle: "Swallow the output and only surface errors." Successful tool outputs are suppressed or heavily summarized; only failures produce verbose output that enters the agent's context window. This reduces token consumption by 52% (JetBrains Research) while preserving the information the agent actually needs to act on -- namely, what went wrong.

### 13.4 Cost-Per-Outcome Tracking

Don't just track cost-per-token. Track **cost-per-completed-task** and **cost-per-quality-unit**:
- Total cost / tasks completed = cost per task
- Total cost / test-passing features = cost per shipped feature
- Compare across harness configurations to optimize

## From §6.14: Model Regression from Provider Updates

- **Symptom**: When a provider updates a model, harness behavior breaks silently. The harness was tuned for specific model behaviors that changed.
- **Evidence**: The report's own Principle 9 ("simplify as models improve") acknowledges positive evolution but not the negative direction.
- **Fix**: Regression test suite for the harness against model changes; pin model versions where stability matters; monitor key metrics after provider updates.

Model regression is a particularly dangerous failure mode because it is invisible until it manifests as degraded agent performance. The harness was designed around specific model behaviors -- how the model responds to certain prompts, how it structures tool calls, how it handles edge cases. When the provider updates the model (often without announcing specific behavioral changes), these assumptions may no longer hold. The harness continues to operate, but its carefully tuned patterns may now be subtly wrong.

This creates a paradox: the harness should be simplified as models improve (Principle 9), but provider updates can also introduce regressions that require *more* harness complexity to compensate. The resolution is continuous monitoring and regression testing, not assuming monotonic improvement.
