### 9.1 Three Tiers

1. **In-Process Subagents**: Same process, isolated context windows (e.g., Claude Code's Agent tool)
2. **Local Orchestrators**: Separate processes coordinated by a parent (e.g., Ralph loop spawning multiple Claude instances)
3. **Cloud Async**: Distributed agents with message-passing (e.g., remote triggers, webhook-based coordination)

(From Section 9 Multi-Agent Orchestration)

---

**Data Exfiltration Through Tool Calls**: Agent sends sensitive data to external services via tool calls (API requests, file uploads, etc.).
- **Mitigation**: Allowlist external endpoints; monitor tool call parameters for sensitive data patterns; require human approval for external communications.

(From Section 12.4 Security Threat Model for Agent Systems)

The cloud async tier (Tier 3) is particularly vulnerable to data exfiltration via bridge channels because:

- Distributed agents with message-passing inherently transmit data across network boundaries
- Remote triggers and webhook-based coordination send context data to external endpoints
- Each agent in the distributed system has its own tool access, multiplying the exfiltration surface
- The bridge between tiers (local orchestrator -> cloud async) is a data leakage channel

From Section 9.3 Agent Communication:
- **File-based communication** is preferred over programmatic handoffs
- One agent writes a structured file; another agent reads it in a fresh context
- **Security caution**: File-based communication persists data to disk. Without cleanup protocols, sensitive data can leak between sessions or between agents working on unrelated tasks. Use ephemeral directories and explicit cleanup for sensitive operations.

From Section 6.15 Data Leakage Between Contexts:
- **Symptom**: Information leaks between sessions, between sub-agents, or through file-based communication
- **Fix**: Context isolation via separate file namespaces; cleanup protocols; avoid logging sensitive data in progress files; use ephemeral directories for sensitive work
