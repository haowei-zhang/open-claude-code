## From §5: Pattern 5 Progressive Context Compaction

5. **Progressive Context Compaction**: Four layers: HISTORY_SNIP, Microcompact, CONTEXT_COLLAPSE, Autocompact

This pattern implements a multi-layered approach to managing context window utilization. As the context window fills, progressively more aggressive compaction strategies are applied:

1. **HISTORY_SNIP**: Remove the oldest conversation turns, preserving recent context and any tool results that are still relevant.
2. **Microcompact**: Summarize recent tool outputs, compressing verbose results into key findings.
3. **CONTEXT_COLLAPSE**: More aggressive summarization of the entire conversation, preserving only the essential task state, decisions made, and current progress.
4. **Autocompact**: Automatic hard reset when context utilization reaches critical thresholds, with structured handoff to a fresh context window.

The key insight is that compaction should be gradual and context-preserving, not abrupt. Each layer removes less critical information first, preserving the most important context for as long as possible.

## From §6.1: Context Rot

- **Symptom**: Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.
- **Fix**: Active context management (summarization, pruning, progress file pattern)

Context rot is one of the most insidious failure modes because it is gradual and often goes unnoticed until significant degradation has occurred. The agent doesn't suddenly fail -- it slowly becomes less coherent, re-visiting decisions it already made, contradicting earlier conclusions, or losing track of the original task goal.

The "mid-window" position is critical: research shows that information at the beginning and end of a context window is more reliably attended to, while information in the middle degrades fastest. This means that as a context window fills, early instructions and later observations are retained, but the reasoning chain in the middle can be lost.
