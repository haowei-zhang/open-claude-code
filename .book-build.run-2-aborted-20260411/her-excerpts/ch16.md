# HER Excerpt for Chapter 16

## From §6.13: Security Vulnerabilities / Prompt Injection

- **Symptom**: Malicious content in files, tool outputs, or user inputs manipulates agent behavior. Can lead to data exfiltration, unauthorized operations, or system prompt leakage.
- **Evidence**: 73% of production AI deployments affected by indirect prompt injection in 2025. The OpenClaw incident (135,000 GitHub stars, 21,000 exposed instances, CVE-2025-53773, CVSS 9.6) is a major real-world case.
- **Fix**: Input sanitization; output filtering; least-privilege tool permissions; treat all external content as untrusted. See Section 12 for detailed security architecture.

Prompt injection is arguably the most serious security threat to agent systems. Unlike traditional software vulnerabilities that exploit code bugs, prompt injection exploits the fundamental nature of LLMs: they cannot reliably distinguish between instructions and data. When a file contains both legitimate content and malicious instructions, the agent may follow the malicious instructions as if they were part of its system prompt.

**Types of prompt injection**:
- **Direct injection**: A user explicitly provides malicious instructions to the agent.
- **Indirect injection**: Malicious instructions are embedded in data that the agent processes (files, web pages, database records, tool outputs). This is more dangerous because the user may not be aware of it.

The OpenClaw incident demonstrates that this is not theoretical. An open-source agent framework with 135,000 GitHub stars had a critical vulnerability (CVSS 9.6) that allowed remote code execution through the agent's tool interface. 21,000 instances were exposed.

## From §6.12: Hallucinated Tool Calls

- **Symptom**: Agent fabricates tool parameters, calls wrong APIs, or reports success on actions that silently failed. Distinct from "Silent Failures" (6.6) -- the agent *invents* tool calls that look structurally valid but are semantically wrong.
- **Evidence**: Per Vectara's "Awesome Agent Failures" collection and Arize's field analysis, this is one of the most common production failures.
- **Fix**: Schema validation on all tool call parameters; semantic validation for critical operations (e.g., verify file exists before editing); replay logs for post-hoc audit.

Hallucinated tool calls differ from silent failures in a crucial way: with silent failures, the tool was called correctly but the result was misinterpreted. With hallucinated tool calls, the agent *invents* parameters that don't exist in the tool schema, or constructs calls that are structurally valid but semantically meaningless. For example, the agent might call a `FileEditTool` with parameters that refer to a file path that doesn't exist, or pass a `mode` parameter that the tool doesn't support but which looks plausible.

The fix requires both schema validation (ensuring tool calls conform to the tool's defined interface) and semantic validation (ensuring the parameters make sense in context -- e.g., the file being edited actually exists).
