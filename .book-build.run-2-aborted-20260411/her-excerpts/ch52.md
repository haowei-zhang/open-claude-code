## 12. Guardrails, Safety, and Security

### 12.1 Five-Layer Defense-in-Depth
1. **Prompt-level guardrails**: Instructions in system prompt about what not to do
2. **Schema-level restrictions**: Tool parameter validation, allowlists
3. **Runtime approval system**: Human-in-the-loop for destructive operations
4. **Tool-level validation**: Per-tool safety checks before execution
5. **Lifecycle hooks**: Deterministic shell commands at lifecycle events

### 12.2 GUARDRAILS.md Protocol
Uses a **Sign** structure: Trigger, Instruction, Reason, Provenance.

### 12.3 Four Universal Safety Patterns
1. **Artifact Verification**: Check generated outputs meet structural requirements
2. **Context Rotation**: Periodically reset context to prevent degradation-induced errors
3. **Privilege Boundaries**: Different agents have different permission levels
4. **Rate Limiting**: Prevent runaway loops and excessive API/tool usage

### 12.4 Security Threat Model for Agent Systems
- **Indirect Prompt Injection**: Malicious instructions in files/tool outputs. Mitigation: input sanitization, treat all external content as untrusted.
- **Supply Chain Attacks via MCP/Skills**: Compromised tools. Mitigation: vet all servers, restrict permissions, audit logs.
- **System Prompt Leakage**: Agent tricked into revealing config. Mitigation: minimize sensitive info in prompts.
- **Data Exfiltration Through Tool Calls**: Sensitive data sent externally. Mitigation: allowlist endpoints, monitor parameters.
- **Checkpoint-Restore Attacks**: Action Replay and Authority Resurrection. Mitigation: record irreversible effects, idempotency keys.

### 12.5 The OpenClaw Incident
135,000 GitHub stars, 21,000 exposed instances, CVE-2025-53773 (CVSS 9.6). Agent security is not theoretical.

### 12.6 Idempotency for External Operations
Generate unique operation ID, check before executing, store results, check on retry/restore.

## 6. Failure Modes and Recovery Patterns (6.11-6.17)

### 6.11 Cost Explosion / Runaway Spending
- Agents in infinite loops or multi-agent chains rack up hundreds or thousands of dollars. TCO underestimated by 40-60%. **For multi-hour tasks, this is arguably the #1 operational risk.**
- **Fix**: Per-session and per-task cost caps; real-time token metering; anomaly detection; dead-letter queues.

### 6.12 Hallucinated Tool Calls
- Agent fabricates tool parameters, calls wrong APIs, or reports success on actions that silently failed.
- **Fix**: Schema validation on all tool call parameters; semantic validation for critical operations; replay logs.

### 6.13 Security Vulnerabilities / Prompt Injection
- Malicious content in files, tool outputs, or user inputs manipulates agent behavior. 73% of deployments affected.
- **Fix**: Input sanitization; output filtering; least-privilege tool permissions; treat all external content as untrusted.

### 6.14 Model Regression from Provider Updates
- Provider updates break harness behavior silently. Harness was tuned for specific model behaviors.
- **Fix**: Regression test suite for the harness; pin model versions; monitor key metrics after updates.

### 6.15 Data Leakage Between Contexts
- Information leaks between sessions, sub-agents, or through file-based communication.
- **Fix**: Context isolation via separate file namespaces; cleanup protocols; ephemeral directories for sensitive work.

### 6.16 Checkpoint-Restore Side Effects
- Agents re-synthesize subtly different requests after restore, causing duplicate payments and unauthorized credential reuse. ACRFence identifies Action Replay and Authority Resurrection.
- **Fix**: Record irreversible tool effects; enforce replay-or-fork semantics; idempotency keys.
- **Critical for multi-hour tasks with external side effects.**

### 6.17 Goal Misinterpretation / Specification Gaming
- Agent optimizes for proxy metrics rather than actual intent. May do significant wrong work rather than stopping early.
- **Fix**: Explicit acceptance criteria with concrete examples; human checkpoint at 25% completion; decompose ambiguous goals.
