### 8. Fork-Join Parallelism
**Multiple subagents in isolated git worktrees; cached parent context reuse**

From the 12 Agentic Harness Patterns (Claude Code-Derived):

### Workflow and Orchestration (3 patterns)

6. **Explore-Plan-Act Loop**: Three phases with escalating permissions (read-only -> discussion -> full access)
7. **Context-Isolated Subagents**: Separate context windows per phase; research agents cannot edit
8. **Fork-Join Parallelism**: Multiple subagents in isolated git worktrees; cached parent context reuse

---

**Checkpoint-Restore Attacks** (ACRFence, arXiv:2603.20625): LLM agents re-synthesize subtly different requests after checkpoint-restore, causing duplicate payments, unauthorized credential reuse, and irreversible side effects. Two attack classes: Action Replay (replaying previously completed actions) and Authority Resurrection (reusing expired credentials).
- **Mitigation**: Record irreversible tool effects; enforce replay-or-fork semantics; use idempotency keys for all external operations.

(From Section 12.4 Security Threat Model for Agent Systems)

**Path traversal defense** is critical for Fork-Join Parallelism because:

- Multiple subagents operate in isolated git worktrees -- each worktree must be sandboxed to prevent path traversal between worktrees
- Cached parent context reuse means the parent's file paths are shared with children -- a subagent must not be able to traverse outside its assigned worktree
- From Section 7.5 Hooks (Lifecycle Events): PreToolUse hooks can enforce file protection rules that prevent path traversal

From Section 9.3 Agent Communication:
- File-based communication is preferred over programmatic handoffs
- Git provides audit trail and rollback capability
- Isolated worktrees for parallel agent work (from Section 21 Layer 7: Multi-Agent Coordination)

From Section 12.3 Four Universal Safety Patterns:
- **Privilege Boundaries**: Different agents have different permission levels (research agents can't edit)
- **Rate Limiting**: Prevent runaway loops and excessive API/tool usage

The fork-join pattern requires that each forked subagent is constrained to its worktree path. Path traversal attacks (e.g., `../../../etc/passwd`) must be blocked at the tool level through deterministic pre-parsing (Pattern 10: Command Risk Classification).
