## From §5: Pattern 3 Tiered Memory

3. **Tiered Memory**: Compact index (200 lines max) always in context; topic files on demand; full transcripts on disk

This pattern implements a three-tier memory architecture inspired by CPU caching:

**Tier 1 -- Always-loaded index**: A compact index (200 lines maximum) that is always present in the context window. This index contains pointers to detailed information stored elsewhere. It provides the agent with a map of what it knows without consuming excessive context space.

**Tier 2 -- On-demand topic files**: Detailed information organized by topic, loaded into context only when needed. When the agent needs information about a specific topic, it reads the corresponding topic file. This keeps the context window focused on the current task while ensuring detailed information is available when required.

**Tier 3 -- Full transcripts on disk**: Complete conversation histories and detailed logs stored on disk but not loaded into context. These serve as an audit trail and can be searched when needed, but they do not consume context window space.

The key benefit is that the agent always has a high-level map of available knowledge (Tier 1) while only loading detailed information (Tier 2) when it's actually needed. Full transcripts (Tier 3) are available for search but never automatically loaded.

## From §7.1: Persistent Instruction File

- Deterministically injected into system prompt every session
- Keep under 60 lines for optimal performance

- **ETH Zurich study** (arXiv:2602.11988, "Evaluating AGENTS.md"): This paper found that **context files tend to reduce task success rates compared to providing no repository context, while also increasing inference cost by over 20%.** This applies to both LLM-generated and developer-committed context files. The paper recommends describing only "minimal requirements" -- verbose instructions and detailed directory trees hurt rather than help.

- Three-part structure recommended (if used): WHY (project context) / WHAT (conventions) / HOW (workflows)
