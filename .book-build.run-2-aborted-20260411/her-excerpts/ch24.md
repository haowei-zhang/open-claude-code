## From §5: Pattern 4 Dream Consolidation

4. **Dream Consolidation**: Background processes review, deduplicate, prune memory during idle time (8 phases, 5 compaction types)

This pattern performs memory maintenance during periods when the agent is not actively working on a task. Named by analogy to sleep consolidation in human memory, it reviews, deduplicates, and prunes the agent's stored context and memory files during idle time.

**8 phases of dream consolidation**:
1. Scan: Review all stored context and memory files
2. Classify: Categorize information by type and relevance
3. Deduplicate: Remove redundant information across files
4. Prune: Remove outdated or irrelevant information
5. Consolidate: Merge related information from multiple sources
6. Compress: Summarize verbose entries into concise form
7. Reorganize: Restructure information for optimal retrieval
8. Verify: Ensure no critical information was lost during consolidation

**5 compaction types**:
- Full transcript to structured notes
- Multiple observations to synthesized findings
- Redundant entries to single canonical entry
- Verbose descriptions to concise summaries
- Time-ordered events to thematic groupings

The key insight is that memory maintenance should happen proactively during idle time, not reactively when context limits are reached. By consolidating memory before it's needed, the agent always has clean, relevant, deduplicated context available.

## From §21: Layer 8 Learning and Adaptation

### Layer 8: Learning and Adaptation
- Progress notes persisted to files (survive context resets)
- Pattern discovery logged to AGENTS.md
- Feedback from evaluator recorded for future sessions
- Stale assumptions pruned as models improve
- Harness configuration versioning and A/B testing (Meta-Harness approach)

Layer 8 is the "meta" layer of the reference architecture. It represents the system's ability to learn from its own operation and adapt over time. Progress notes and pattern discoveries are persisted to files so they survive context resets. Evaluator feedback is recorded for future sessions. Critically, stale assumptions are pruned as models improve -- the harness must not become a fossil of outdated workarounds. The Meta-Harness approach (arXiv:2603.28052) suggests that harness configurations can be systematically optimized through A/B testing rather than relying solely on human intuition.
