## From §5: The 12 Agentic Harness Patterns (Index)

### Memory and Context (5 patterns)

1. **Persistent Instruction File**: CLAUDE.md auto-loaded at session start
2. **Scoped Context Assembly**: Multi-level instruction loading (org -> user -> project -> directory)
3. **Tiered Memory**: Compact index (200 lines max) always in context; topic files on demand; full transcripts on disk
4. **Dream Consolidation**: Background processes review, deduplicate, prune memory during idle time (8 phases, 5 compaction types)
5. **Progressive Context Compaction**: Four layers: HISTORY_SNIP, Microcompact, CONTEXT_COLLAPSE, Autocompact

### Workflow and Orchestration (3 patterns)

6. **Explore-Plan-Act Loop**: Three phases with escalating permissions (read-only -> discussion -> full access)
7. **Context-Isolated Subagents**: Separate context windows per phase; research agents cannot edit
8. **Fork-Join Parallelism**: Multiple subagents in isolated git worktrees; cached parent context reuse

### Tools and Permissions (3 patterns)

9. **Progressive Tool Expansion**: Start with <20 tools; activate more on demand (not all 60+ at once)
10. **Command Risk Classification**: Deterministic pre-parsing and per-tool permission gating
11. **Single-Purpose Tool Design**: FileReadTool, FileEditTool, GrepTool each with individual permission rules

### Automation (1 pattern)

12. **Deterministic Lifecycle Hooks**: Shell commands at 25+ lifecycle points (PreToolUse, PostToolUse, SessionStart, etc.)

## From §6: Failure Modes and Recovery Patterns (Index)

Across all sources, these failure modes are consistently identified. The first 10 are from the original survey; items 6.11-6.17 were identified through audit and additional research.

### 6.1 Context Rot
Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.

### 6.2 Premature Completion
Agent declares work done too early. Fix: Comprehensive JSON feature list with all items initially marked "failing".

### 6.3 Self-Evaluation Bias
Agent rates own work too generously. Fix: Separate evaluator agent in a fresh context window.

### 6.4 Placeholder Implementations
Agents default to stubs because compiling triggers reward signals. Fix: Explicit anti-placeholder instructions.

### 6.5 Context Anxiety
Models prematurely wrap up near perceived context limits. Fix: Context resets with structured handoffs.

### 6.6 Silent Failures
Agent proceeds after tool errors as if successful. Fix: Structured output validation after every tool call.

### 6.7 Infinite Loops
Retry without progress. Fix: Maximum retry counts, exponential backoff, loop detection.

### 6.8 Tool Explosion
Too many tools degrade selection accuracy. Fix: Progressive tool expansion starting with <20.

### 6.9 Compounding Bugs Across Sessions
New session builds on broken state from previous session. Fix: Baseline verification at session start.

### 6.10 Yak Shaving / Scope Creep
Agent wanders into tangential fixes. Fix: Strict single-task-per-session constraint.

### 6.11 Cost Explosion / Runaway Spending
Agents in infinite loops or multi-agent chains rack up hundreds or thousands of dollars. Fix: Per-session and per-task cost caps; real-time token metering.

### 6.12 Hallucinated Tool Calls
Agent fabricates tool parameters or reports success on actions that silently failed. Fix: Schema validation on all tool call parameters.

### 6.13 Security Vulnerabilities / Prompt Injection
Malicious content in files, tool outputs, or user inputs manipulates agent behavior. Fix: Input sanitization; output filtering; least-privilege tool permissions.

### 6.14 Model Regression from Provider Updates
When a provider updates a model, harness behavior breaks silently. Fix: Regression test suite; pin model versions where stability matters.

### 6.15 Data Leakage Between Contexts
Information leaks between sessions, between sub-agents, or through file-based communication. Fix: Context isolation via separate file namespaces; cleanup protocols.

### 6.16 Checkpoint-Restore Side Effects
LLM agents re-synthesize subtly different requests after restore, causing duplicate payments, unauthorized credential reuse. Fix: Record irreversible tool effects; enforce replay-or-fork semantics.

### 6.17 Goal Misinterpretation / Specification Gaming
Agent optimizes for proxy metrics rather than actual intent. Fix: Explicit acceptance criteria with concrete examples.

## From §20: 12 Best Practices (Index)

Synthesized from the four canonical sources, academic research, practitioner data, and honest failure analysis:

1. **Context windows are the constraint; structured artifacts are the solution.** Task lists (JSON, not Markdown), progress notes, and git history bridge sessions.

2. **Separate generation from evaluation.** Agents are reliably bad at grading their own work.

3. **One task per session.** This single rule prevents more failures than almost anything else.

4. **Verify before building.** Always run a baseline check at session start.

5. **Wire in fast feedback loops.** Tests, linters, type checkers, and UI automation provide deterministic back-pressure.

6. **Repository is single source of truth.** All state must be persisted to files and git.

7. **Humans steer, agents execute.** Senior expertise remains essential.

8. **Expect eventual consistency.** Most issues resolve through more loops with better prompts.

9. **Simplify relentlessly.** Strip unneeded harness complexity as models improve.

10. **Control costs actively.** Set per-session and per-task cost caps. Monitor spend rate in real-time.

11. **Observe everything.** If you can't see what the agent is doing, you can't fix it when it goes wrong.

12. **Secure by default.** Treat all external content as untrusted. Use least-privilege permissions.
