## From §5: Pattern 5 Progressive Context Compaction

5. **Progressive Context Compaction**: Four layers: HISTORY_SNIP, Microcompact, CONTEXT_COLLAPSE, Autocompact

This pattern implements a multi-layered approach to managing context window utilization. As the context window fills, progressively more aggressive compaction strategies are applied:

1. **HISTORY_SNIP**: Remove the oldest conversation turns, preserving recent context and any tool results that are still relevant.
2. **Microcompact**: Summarize recent tool outputs, compressing verbose results into key findings.
3. **CONTEXT_COLLAPSE**: More aggressive summarization of the entire conversation, preserving only the essential task state, decisions made, and current progress.
4. **Autocompact**: Automatic hard reset when context utilization reaches critical thresholds, with structured handoff to a fresh context window.

## From §8: Context Management Strategies

### 8.1 Six Techniques (Author's Synthesis)

**Note**: The following ranking is the report author's synthesis based on available evidence, not an empirically validated ordering. The "best" technique depends on workload, model, and cost constraints.

1. **Observation Masking** (strong cost-efficiency evidence): 52% cost reduction by hiding irrelevant tool outputs (JetBrains Research, verified). "Swallow the output and only surface errors."
2. **LLM Summarization**: Use a cheaper model to compress verbose outputs before injecting into main context
3. **Progressive Compaction**: 5-stage system at configurable token thresholds (HISTORY_SNIP -> Microcompact -> CONTEXT_COLLAPSE -> Autocompact -> Hard reset)
4. **Structured Note-Taking**: Agent maintains its own progress notes in files, which survive context resets
5. **Sub-Agent Isolation**: Research happens in separate context windows, only findings return to parent
6. **Per-Tool-Type Summarization**: Different compression strategies for different tool outputs (build logs vs. file reads vs. search results)

### 8.1 Observation Masking

**Observation masking** is the single most effective cost optimization with verified evidence. The principle: "Swallow the output and only surface errors." Successful tool outputs are suppressed or heavily summarized; only failures produce verbose output that enters the agent's context window. This reduces token consumption by 52% (JetBrains Research) while preserving the information the agent actually needs to act on.

## From §6.1: Context Rot

- **Symptom**: Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.
- **Fix**: Active context management (summarization, pruning, progress file pattern)

Context rot is one of the most insidious failure modes because it is gradual and often goes unnoticed until significant degradation has occurred. The "mid-window" position is critical: information at the beginning and end of a context window is more reliably attended to, while information in the middle degrades fastest.
