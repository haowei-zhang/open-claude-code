## From §9.1: Three Tiers of Multi-Agent Orchestration

1. **In-Process Subagents**: Same process, isolated context windows (e.g., Claude Code's Agent tool)
2. **Local Orchestrators**: Separate processes coordinated by a parent (e.g., Ralph loop spawning multiple Claude instances)
3. **Cloud Async**: Distributed agents with message-passing (e.g., remote triggers, webhook-based coordination)

Each tier represents a fundamentally different architectural approach with different tradeoffs:

**In-Process Subagents** offer the tightest integration and lowest latency. The parent agent can directly invoke sub-agents and receive structured results. Context isolation is enforced at the application level. This tier is best for tasks where the sub-agent's work is tightly coupled to the parent's workflow.

**Local Orchestrators** provide more isolation and flexibility. Each agent runs as a separate process, communicating through files or pipes. This tier is best when agents need independent execution environments or when the orchestrator needs to manage agent lifecycles independently.

**Cloud Async** enables distributed agent work across multiple machines. Agents communicate through message queues, webhooks, or shared storage. This tier is best for tasks that require significant compute resources or that span long time periods where the orchestrator may not be continuously running.

## From §6.5: Context Anxiety

- **Symptom**: Models prematurely wrap up near perceived context limits
- **Fix**: Context resets with structured handoffs rather than pushing to the limit

Context anxiety is a subtle failure mode where the model, aware that context window space is limited, begins to rush its work. Rather than completing tasks thoroughly, it starts cutting corners, skipping verification steps, and declaring work done prematurely -- all because it perceives (correctly or incorrectly) that it is running out of context space.

The fix is counterintuitive: rather than trying to squeeze more work into a single context window, it's better to explicitly reset the context and start a fresh session with a structured handoff. This gives the model a full context window to work with, eliminating the anxiety that causes premature completion.

Anthropic's research found that context resets with structured handoffs proved more effective than compaction for Claude Sonnet 4.5. The model performs better with a clean context and a clear handoff document than with a compressed version of its entire history.
