# HER Excerpt for Chapter 15

## From §5: Pattern 9 Progressive Tool Expansion

9. **Progressive Tool Expansion**: Start with <20 tools; activate more on demand (not all 60+ at once)

This pattern addresses the Tool Explosion failure mode directly. Rather than presenting all available tools to the model at once, the harness starts with a small, essential subset and activates additional tools only when contextually needed.

**The problem it solves**: When an agent has too many tools simultaneously, tool descriptions compete for attention in the context window. The model's ability to discriminate between similar tools degrades as the number grows. Research and practitioner experience suggest that performance degrades significantly beyond 20-30 simultaneous tools.

**How it works**:
- **Base toolset** (always available): File read, file edit, grep, bash, glob. These core tools handle the majority of agent work.
- **On-demand tools** (activated contextually): Specialized tools like web search, notebook editing, MCP server tools. These are activated only when the task requires them.
- **Skill-based activation**: Tools can be bundled into "skills" -- sets of instructions and capabilities that are loaded together when the task context demands them.

**Key benefit**: The agent always has a manageable set of tool options, improving selection accuracy while still providing access to specialized capabilities when needed. This is the tool-design equivalent of scoped context assembly -- load only what's relevant.

## From §6.8: Tool Explosion

- **Symptom**: Too many tools degrade selection accuracy
- **Fix**: Progressive tool expansion starting with <20

When the agent has too many tools available simultaneously, it struggles to select the correct one. The tool descriptions compete for attention in the context window, and the model's ability to discriminate between similar tools degrades as the number grows. This is sometimes called entering "the dumb zone" -- the model has so many options that it makes worse choices than it would with fewer, more focused tools.

The fix is progressive tool expansion: start with a small set of essential tools (typically under 20), and activate additional tools only when contextually needed. This keeps the tool selection problem tractable while still providing access to specialized capabilities when required.
