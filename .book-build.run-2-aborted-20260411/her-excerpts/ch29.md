## From §6.16: Checkpoint-Restore Side Effects (ACRFence)

- **Symptom**: LLM agents re-synthesize subtly different requests after restore, causing duplicate payments, unauthorized credential reuse, and irreversible side effects.
- **Evidence**: The ACRFence paper (arXiv:2603.20625) identifies two attack classes -- Action Replay and Authority Resurrection -- specific to agent checkpoint-restore.
- **Fix**: Record irreversible tool effects; enforce replay-or-fork semantics; idempotency keys for external tool calls (see Section 12.6).
- **Critical for multi-hour tasks with external side effects (API calls, payments, email sends).**

The ACRFence paper (arXiv:2603.20625, authors: Yusheng Zheng, Yiwei Yang, Wei Zhang, Andi Quinn, UC Santa Cruz and University of Connecticut) identifies a novel threat model specific to agent checkpoint-restore:

**Action Replay**: After a checkpoint-restore cycle, the agent may re-synthesize a slightly different version of a request it already executed. If the original request had irreversible side effects (e.g., sending an email, processing a payment), the replay causes duplicate side effects.

**Authority Resurrection**: After restore, the agent may reuse credentials or permissions that have since expired or been revoked. The restored agent doesn't know that its authority has changed.

**Proposed solution (ACRFence)**: Record irreversible tool effects; enforce replay-or-fork semantics (if an action was already completed, replay the stored result rather than re-executing); use idempotency keys for all external operations.

## From §10.3: Session Protocol

Synthesized across Anthropic, OpenAI, and practitioner sources:

```
1. ORIENT     -- Read workspace state (pwd, git log, progress file)
2. SETUP      -- Run init script, install dependencies if needed
3. VERIFY     -- Run baseline tests/checks (CRITICAL: before any new work)
4. SELECT     -- Pick exactly one task from the task list
5. IMPLEMENT  -- Write code with frequent git commits
6. TEST       -- Run tests, lint, type-check (automated back-pressure)
7. UPDATE     -- Update task list status, progress notes, git commit
8. EXIT       -- Clean exit with state fully persisted
```
