# HER Excerpt for Chapter 22

## From §10.1: One-Task-Per-Session Rule

This is the single most impactful rule across all sources. It prevents:
- Context exhaustion mid-feature
- Scope creep and yak shaving
- Compounding errors
- Lost progress due to context resets

The one-task-per-session rule constrains the agent to work on exactly one task per session. This is not merely a preference -- it is a structural constraint that prevents the most common failure modes in multi-hour agent work. When an agent tries to tackle multiple tasks in a single session, it inevitably runs into context limits, loses track of progress on earlier tasks, and produces lower quality work across all tasks than it would have produced on any single one.

## From §8.2: Three-File State Pattern

Across multiple sources, this pattern emerges for state persistence:

```
tasks.json       -- Structured task list (append-only status updates)
progress.txt     -- Human-readable progress notes and learnings
AGENTS.md        -- Discovered patterns and conventions
```

These three files, combined with git history, provide complete session-to-session continuity.

**On JSON vs. Markdown for task lists**: Multiple sources (Anthropic, Reddit/celesteanders) favor JSON with boolean pass/fail and append-only constraints. The rationale: JSON is machine-parseable, boolean status prevents ambiguous "partial" states, and append-only prevents the agent from "editing away" failures. However, Martin Fowler and other sources use Markdown-based approaches successfully. The choice depends on how much you trust the agent not to game the tracking mechanism.

## From §10.3: Session Protocol

Synthesized across Anthropic, OpenAI, and practitioner sources:

```
1. ORIENT     -- Read workspace state (pwd, git log, progress file)
2. SETUP      -- Run init script, install dependencies if needed
3. VERIFY     -- Run baseline tests/checks (CRITICAL: before any new work)
4. SELECT     -- Pick exactly one task from the task list
5. IMPLEMENT  -- Write code with frequent git commits
6. TEST       -- Run tests, lint, type-check (automated back-pressure)
7. UPDATE     -- Update task list status, progress notes, git commit
8. EXIT       -- Clean exit with state fully persisted
```

The Session Protocol is the universal pattern for structured agent sessions. Every session follows the same sequence, ensuring consistent behavior and complete state persistence across sessions. The VERIFY step is critical -- it catches compounding bugs before new work begins.
