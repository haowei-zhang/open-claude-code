## 21. Reference Architecture for a Production Harness (Aspirational)

**IMPORTANT**: This architecture is synthesized from multiple sources that each solve different problems. **No public implementation covers all eight layers.** The celesteanders/harness repo (cited as a reference implementation) implements only Layers 1-2 and part of Layer 4. Combining patterns into one stack does not mean the combination has been validated. Treat this as a reference for what a comprehensive system *could* look like, not as a proven blueprint.

### Layer 1: Task Infrastructure
- JSON task list (append-only, boolean pass/fail)
- Task decomposition into session-sized units (15-30 min target)
- Priority ordering and dependency tracking
- Immutable task descriptions, mutable status only

### Layer 2: Session Management
- Session startup protocol (orient -> setup -> verify -> select)
- Clean exit protocol (update state -> commit -> persist notes)
- Session-to-session handoff via structured files
- Maximum session duration limits with graceful wind-down

### Layer 3: Context Engineering
- Progressive compaction at token thresholds
- Observation masking (suppress successful outputs)
- Tiered memory (always-loaded index + on-demand topic files)
- Sub-agent isolation for research/exploration
- Context reset with structured handoff when degradation detected

### Layer 4: Quality Gates (Back-Pressure)
- Pre-commit: type-check, lint, format
- Post-commit: unit tests, integration tests
- Per-feature: E2E browser automation
- Per-session: evaluator agent in fresh context
- Success is silent; only failures produce verbose output

### Layer 5: Safety and Security Infrastructure
- Permission tiers (read-only -> discuss -> full access)
- Destructive operation confirmation
- File protection rules
- Loop detection and maximum retry limits
- Rate limiting on tool usage
- Input sanitization for prompt injection
- Idempotency keys for external operations
- Checkpoint-restore safety (ACRFence principles)

### Layer 6: Cost and Observability
- Per-session and per-task cost caps
- Real-time token metering and anomaly detection
- Distributed tracing (OpenTelemetry) across multi-agent workflows
- Structured logging of agent decisions and tool calls
- Dashboard for multi-hour session monitoring
- Alerting on degradation patterns (loop detection, context rot, cost spikes)

### Layer 7: Multi-Agent Coordination
- Generator-Evaluator pattern for quality-critical work
- Model routing (expensive for planning, cheap for execution)
- File-based inter-agent communication
- Git-based conflict resolution
- Isolated worktrees for parallel agent work
- Human-in-the-loop escalation paths

### Layer 8: Learning and Adaptation
- Progress notes persisted to files (survive context resets)
- Pattern discovery logged to AGENTS.md
- Feedback from evaluator recorded for future sessions
- Stale assumptions pruned as models improve
- Harness configuration versioning and A/B testing (Meta-Harness approach)
