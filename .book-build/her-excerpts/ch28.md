## 5. The 12 Agentic Harness Patterns (Claude Code-Derived)

Source: [12 Agentic Harness Patterns from Claude Code](https://generativeprogrammer.com/p/12-agentic-harness-patterns-from)

**Important caveat**: These patterns are derived from reverse-engineering Claude Code's architecture. They represent implementation decisions of one specific product (CLI-first, Anthropic-native). Other platforms make fundamentally different tradeoffs: Cursor embeds the harness in an IDE with rich UI; Devin runs fully autonomously; OpenAI Codex uses sandboxed cloud environments. These patterns are useful as concrete examples but should not be treated as universal harness principles.

### Memory and Context (5 patterns)

1. **Persistent Instruction File**: CLAUDE.md auto-loaded at session start
2. **Scoped Context Assembly**: Multi-level instruction loading (org -> user -> project -> directory)
3. **Tiered Memory**: Compact index (200 lines max) always in context; topic files on demand; full transcripts on disk
4. **Dream Consolidation**: Background processes review, deduplicate, prune memory during idle time (8 phases, 5 compaction types)
5. **Progressive Context Compaction**: Four layers: HISTORY_SNIP, Microcompact, CONTEXT_COLLAPSE, Autocompact

### Workflow and Orchestration (3 patterns)

6. **Explore-Plan-Act Loop**: Three phases with escalating permissions (read-only -> discussion -> full access)
7. **Context-Isolated Subagents**: Separate context windows per phase; research agents cannot edit
8. **Fork-Join Parallelism**: Multiple subagents in isolated git worktrees; cached parent context reuse

### Tools and Permissions (3 patterns)

9. **Progressive Tool Expansion**: Start with <20 tools; activate more on demand (not all 60+ at once)
10. **Command Risk Classification**: Deterministic pre-parsing and per-tool permission gating
11. **Single-Purpose Tool Design**: FileReadTool, FileEditTool, GrepTool each with individual permission rules

### Automation (1 pattern)

12. **Deterministic Lifecycle Hooks**: Shell commands at 25+ lifecycle points (PreToolUse, PostToolUse, SessionStart, etc.)

### Equivalent Patterns in Other Platforms

| Concept | Claude Code | Cursor | Devin |
|---------|------------|--------|-------|
| Instruction file | CLAUDE.md | .cursor/rules (with glob scoping) | Internal prompts |
| Context management | Progressive compaction | Model-aware tuning per model | Autonomous session management |
| Subagents | Agent tool with worktrees | Background Composer agents | Built-in multi-step orchestration |
| Tool permissions | Risk classification + hooks | IDE-integrated permission UI | Sandboxed execution environment |
| Verification | External evaluator agent | Built-in linting/testing integration | PR-based verification + human review |

## §8 Context Management

## 8. Context Management Strategies

### 8.1 Six Techniques (Author's Synthesis)

**Note**: The following ranking is the report author's synthesis based on available evidence, not an empirically validated ordering. The "best" technique depends on workload, model, and cost constraints.

1. **Observation Masking** (strong cost-efficiency evidence): 52% cost reduction by hiding irrelevant tool outputs (JetBrains Research, verified). "Swallow the output and only surface errors."
2. **LLM Summarization**: Use a cheaper model to compress verbose outputs before injecting into main context
3. **Progressive Compaction**: 5-stage system at configurable token thresholds (HISTORY_SNIP -> Microcompact -> CONTEXT_COLLAPSE -> Autocompact -> Hard reset)
4. **Structured Note-Taking**: Agent maintains its own progress notes in files, which survive context resets
5. **Sub-Agent Isolation**: Research happens in separate context windows, only findings return to parent
6. **Per-Tool-Type Summarization**: Different compression strategies for different tool outputs (build logs vs. file reads vs. search results)

### 8.2 The Three-File State Pattern

Across multiple sources, this pattern emerges for state persistence:

```
tasks.json       -- Structured task list (append-only status updates)
progress.txt     -- Human-readable progress notes and learnings
AGENTS.md        -- Discovered patterns and conventions
```

These three files, combined with git history, provide complete session-to-session continuity.

**On JSON vs. Markdown for task lists**: Multiple sources (Anthropic, Reddit/celesteanders) favor JSON with boolean pass/fail and append-only constraints. The rationale: JSON is machine-parseable, boolean status prevents ambiguous "partial" states, and append-only prevents the agent from "editing away" failures. However, Martin Fowler and other sources use Markdown-based approaches successfully. The choice depends on how much you trust the agent not to game the tracking mechanism.

### 8.3 Context Window as "Perception"

From the academic paper on terminal coding agents:
- **Filesystem** = long-term memory
- **RAM/variables** = working memory
- **Context window** = perception (what the agent can currently "see")

The harness's job is to manage what enters and exits perception at the right time.

## §6.1 Context Rot

### 6.1 Context Rot
- **Symptom**: Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.
- **Fix**: Active context management (summarization, pruning, progress file pattern)
