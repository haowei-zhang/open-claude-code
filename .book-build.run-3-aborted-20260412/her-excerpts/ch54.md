## 6. Failure Modes and Recovery Patterns

Across all sources, these failure modes are consistently identified. The first 10 are from the original survey; items 6.11-6.17 were identified through audit and additional research.

### 6.1 Context Rot
- **Symptom**: Performance degrades 30%+ when key content falls in mid-window positions. Agent re-solves problems, contradicts itself, loses track of goals.
- **Fix**: Active context management (summarization, pruning, progress file pattern)

### 6.2 Premature Completion
- **Symptom**: Agent declares work done too early
- **Fix**: Comprehensive JSON feature list with all items initially marked "failing"

### 6.3 Self-Evaluation Bias
- **Symptom**: Agent rates own work too generously
- **Fix**: Separate evaluator agent in a fresh context window

### 6.4 Placeholder Implementations
- **Symptom**: Agents default to stubs because compiling triggers reward signals
- **Fix**: Explicit anti-placeholder instructions ("DO NOT IMPLEMENT PLACEHOLDER OR SIMPLE IMPLEMENTATIONS")

### 6.5 Context Anxiety
- **Symptom**: Models prematurely wrap up near perceived context limits
- **Fix**: Context resets with structured handoffs rather than pushing to the limit

### 6.6 Silent Failures
- **Symptom**: Agent proceeds after tool errors as if successful
- **Fix**: Structured output validation after every tool call

### 6.7 Infinite Loops
- **Symptom**: Retry without progress
- **Fix**: Maximum retry counts, exponential backoff, loop detection

### 6.8 Tool Explosion
- **Symptom**: Too many tools degrade selection accuracy
- **Fix**: Progressive tool expansion starting with <20

### 6.9 Compounding Bugs Across Sessions
- **Symptom**: New session builds on broken state from previous session
- **Fix**: Baseline verification at session start before any new work

### 6.10 Yak Shaving / Scope Creep
- **Symptom**: Agent wanders into tangential fixes
- **Fix**: Strict single-task-per-session constraint, explicit task boundaries

### 6.11 Cost Explosion / Runaway Spending
- **Symptom**: Agents in infinite loops or multi-agent chains rack up hundreds or thousands of dollars. Token costs in multi-agent systems compound non-linearly.
- **Evidence**: Per CIO research, enterprise budgets underestimate AI agent TCO by 40-60%. Geoffrey Huntley's $297 success story could easily have been $2,970 without monitoring.
- **Fix**: Per-session and per-task cost caps; real-time token metering; anomaly detection on spend rate; dead-letter queues for tasks exceeding thresholds.
- **For multi-hour tasks, this is arguably the #1 operational risk.**

### 6.12 Hallucinated Tool Calls
- **Symptom**: Agent fabricates tool parameters, calls wrong APIs, or reports success on actions that silently failed. Distinct from "Silent Failures" (6.6) -- the agent *invents* tool calls that look structurally valid but are semantically wrong.
- **Evidence**: Per Vectara's "Awesome Agent Failures" collection and Arize's field analysis, this is one of the most common production failures.
- **Fix**: Schema validation on all tool call parameters; semantic validation for critical operations (e.g., verify file exists before editing); replay logs for post-hoc audit.

### 6.13 Security Vulnerabilities / Prompt Injection
- **Symptom**: Malicious content in files, tool outputs, or user inputs manipulates agent behavior. Can lead to data exfiltration, unauthorized operations, or system prompt leakage.
- **Evidence**: 73% of production AI deployments affected by indirect prompt injection in 2025. The OpenClaw incident (135,000 GitHub stars, 21,000 exposed instances, CVE-2025-53773, CVSS 9.6) is a major real-world case.
- **Fix**: Input sanitization; output filtering; least-privilege tool permissions; treat all external content as untrusted. See Section 12 for detailed security architecture.

### 6.14 Model Regression from Provider Updates
- **Symptom**: When a provider updates a model, harness behavior breaks silently. The harness was tuned for specific model behaviors that changed.
- **Evidence**: The report's own Principle 9 ("simplify as models improve") acknowledges positive evolution but not the negative direction.
- **Fix**: Regression test suite for the harness against model changes; pin model versions where stability matters; monitor key metrics after provider updates.

### 6.15 Data Leakage Between Contexts
- **Symptom**: Information leaks between sessions, between sub-agents, or through file-based communication.
- **Evidence**: File-based communication (recommended in Section 9.3) inherently persists data to disk. Without cleanup, sensitive data from one task context can bleed into another.
- **Fix**: Context isolation via separate file namespaces; cleanup protocols; avoid logging sensitive data in progress files; use ephemeral directories for sensitive work.

### 6.16 Checkpoint-Restore Side Effects
- **Symptom**: LLM agents re-synthesize subtly different requests after restore, causing duplicate payments, unauthorized credential reuse, and irreversible side effects.
- **Evidence**: The ACRFence paper (arXiv:2603.20625) identifies two attack classes -- Action Replay and Authority Resurrection -- specific to agent checkpoint-restore.
- **Fix**: Record irreversible tool effects; enforce replay-or-fork semantics; idempotency keys for external tool calls (see Section 12.6).
- **Critical for multi-hour tasks with external side effects (API calls, payments, email sends).**

### 6.17 Goal Misinterpretation / Specification Gaming
- **Symptom**: Agent optimizes for proxy metrics rather than actual intent. Distinct from "Premature Completion" (6.2) -- the agent may do significant *wrong* work rather than stopping early.
- **Evidence**: Devin's production data confirms agents struggle with ambiguous requirements. Performance degrades significantly when users give mid-task scope changes.
- **Fix**: Explicit acceptance criteria with concrete examples; human checkpoint at 25% completion for intent verification; decompose ambiguous goals into unambiguous sub-tasks before starting.
