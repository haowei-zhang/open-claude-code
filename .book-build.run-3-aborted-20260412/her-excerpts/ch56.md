### §11

## 11. Human-in-the-Loop Design Patterns

The canonical sources state "Humans steer, agents execute" but rarely detail the specific patterns for how humans participate in agent workflows. For multi-hour tasks, these patterns are essential.

### 11.1 Confidence-Based Routing
- **Above threshold** (e.g., 90% confidence): Agent proceeds autonomously
- **Below threshold**: Agent queues the decision for human approval, continues with other work
- **Implementation**: The agent reports its confidence and reasoning; a routing layer (which can be deterministic or model-based) decides whether to proceed or escalate

### 11.2 Tiered Escalation
- **Tier 1** (automated): Deterministic checks handle (linting, testing, formatting)
- **Tier 2** (agent self-correction): Agent gets feedback from Tier 1 and tries again
- **Tier 3** (human front-line): Moderate-risk decisions (e.g., "should I refactor this module?")
- **Tier 4** (human expert): High-risk decisions (architecture changes, security-sensitive operations, production deployments)

### 11.3 Async Approval
- Agent parks a blocked action, records context about what it tried and why it's uncertain
- Agent continues with non-blocked work
- When human approves/denies, agent resumes the blocked work path
- **Critical for multi-hour tasks**: The agent should never fully block on human input. Always have a queue of independent tasks to work on while waiting.

### 11.4 Context-Rich Escalation
When the agent escalates to a human, it must provide:
- What it was trying to do
- What it tried
- Why it failed or is uncertain
- What options it sees
- What it recommends (if it has a preference)

This prevents the human from having to reconstruct full context from scratch.

### 11.5 Handoff Protocols
- **Full context transfer**: Agent writes a structured handoff document summarizing current state, what's done, what's remaining, and any open questions
- **Incremental review**: Human reviews completed chunks (e.g., every 3 tasks) rather than waiting for the end
- **Checkpoint review**: Mandatory human review at 25% and 75% of task completion to catch goal misinterpretation early

### §13

## 13. Cost Management and Budgeting

**This section addresses the most conspicuous gap in the original harness engineering literature.** Per CIO research, enterprise budgets underestimate AI agent TCO by 40-60%. For multi-hour tasks, uncontrolled cost is the #1 operational risk.

### 13.1 Cost Failure Modes

- **Infinite loops**: An agent in a retry loop can consume thousands of tokens per minute
- **Multi-agent amplification**: Generator + evaluator + sub-agents compound token costs non-linearly
- **Context window bloat**: Approaching context limits triggers expensive compaction operations or session resets
- **Model routing failures**: Expensive model used for tasks that a cheaper model could handle

### 13.2 Cost Control Architecture

```
Per-task cost cap         -- Hard limit; task fails gracefully if exceeded
Per-session cost cap      -- Prevents runaway sessions
Per-hour spend rate alert -- Anomaly detection on spend velocity
Dead-letter queue         -- Tasks exceeding thresholds get queued for human review
Budget allocation         -- Separate budgets for generator/evaluator/sub-agents
```

### 13.3 Cost Optimization Strategies

1. **Semantic routing**: Route simple sub-tasks (summarization, classification) to cheap models (Haiku); reserve expensive models (Opus) for planning and complex reasoning
2. **Observation masking**: 52% cost reduction by hiding irrelevant tool outputs (JetBrains Research, verified)
3. **Sub-agent isolation**: Research in cheap-model sub-agents rather than expensive parent context
4. **Early termination**: Kill sessions that are clearly stuck (loop detection, no-progress-for-N-minutes)
5. **Token metering**: Real-time tracking of input/output tokens per session, per task, per agent

### 13.4 Cost-Per-Outcome Tracking

Don't just track cost-per-token. Track **cost-per-completed-task** and **cost-per-quality-unit**:
- Total cost / tasks completed = cost per task
- Total cost / test-passing features = cost per shipped feature
- Compare across harness configurations to optimize

### 13.5 Budget Reality Check

| Metric | Source |
|--------|--------|
| $297 for a $50k contract (best case) | Geoffrey Huntley/Ralph |
| $200 for 6 hours of harness work | Anthropic |
| $3,200-$13,000/month per agent (enterprise) | CIO research |
| 40-60% TCO underestimation | CIO research |

The success stories ($297, $200) represent optimal outcomes with expert human steering. Budget for 3-10x these figures for realistic multi-hour production use.

### §14

## 14. Observability and Monitoring

Per LangChain's State of Agent Engineering survey (1,340 respondents, Nov-Dec 2025), **89% of organizations with production agents have implemented observability** (94% among those with agents in production). 62% have detailed per-step tracing. This is table stakes, not optional.

### 14.1 Three Pillars for Agent Observability

1. **Traces**: Distributed tracing across multi-agent workflows. Each tool call, sub-agent dispatch, and model invocation is a span. OpenTelemetry semantic conventions for AI agent traces are emerging.

2. **Metrics**: Per-session and per-task metrics:
   - Token usage (input/output, per model)
   - Cost accrual rate
   - Tool call latency and success rates
   - Task completion rate and time-to-completion
   - Context window utilization (% of max)

3. **Logs**: Structured logging of agent decisions, tool call parameters/results, and state transitions. Critical for post-hoc debugging of "why did the agent do X?"

### 14.2 The Observability Gap

Agents fail silently because their response format looks correct. A 200 OK from a tool call doesn't mean the operation succeeded semantically. Observability must go beyond "did the API call return?" to "did the operation achieve its intended effect?"

### 14.3 Multi-Hour Session Dashboard

For multi-hour tasks, the operator needs visibility into:
- **Progress**: How many tasks completed vs. remaining?
- **Health**: Is the agent making progress or stuck in a loop?
- **Cost**: Cumulative spend and spend rate
- **Context**: How full is the context window? When was the last reset?
- **Quality**: Evaluator scores over time -- are they trending down?
- **Alerts**: Degradation pattern detection (context rot, loop detection, cost anomaly)

### 14.4 Alerting Patterns

- **Loop detection**: Same tool called with same parameters N times in M minutes
- **Context rot signal**: Agent re-solves a problem it already solved (detected via semantic similarity of tool calls)
- **Cost spike**: Spend rate exceeds 2x the rolling average
- **Quality degradation**: Evaluator scores drop below threshold for N consecutive evaluations
- **Staleness**: No progress file update or git commit for N minutes

### §20

## 20. Synthesized Best Practices

### The 12 Core Principles

Synthesized from the four canonical sources, academic research, practitioner data, and honest failure analysis:

1. **Context windows are the constraint; structured artifacts are the solution.** Task lists (JSON, not Markdown), progress notes, and git history bridge sessions. If it's not in the repo, it doesn't exist for the agent.

2. **Separate generation from evaluation.** Agents are reliably bad at grading their own work. A standalone skeptical evaluator is far easier to tune than making a generator self-critical. But be aware of the Ouroboros problem -- deterministic evaluation (tests, linters) is more reliable than LLM evaluation.

3. **One task per session.** This single rule prevents more failures than almost anything else.

4. **Verify before building.** Always run a baseline check at session start. Compounding bugs across sessions is one of the most common failure modes.

5. **Wire in fast feedback loops.** Tests, linters, type checkers, and UI automation provide deterministic back-pressure that catches errors the agent won't notice.

6. **Repository is single source of truth.** All state must be persisted to files and git. Context windows are ephemeral; the repo is permanent.

7. **Humans steer, agents execute.** Senior expertise in task selection, architecture decisions, and quality judgment remains essential. The harness amplifies human judgment, not replaces it. Design explicit human-in-the-loop checkpoints for multi-hour tasks.

8. **Expect eventual consistency.** Most issues resolve through more loops with better prompts. The speed of the loop matters more than perfection in any single iteration.

9. **Simplify relentlessly.** Strip unneeded harness complexity as models improve. Every component encodes an assumption about model limitations -- these go stale fast.

10. **Control costs actively.** Set per-session and per-task cost caps. Monitor spend rate in real-time. Budget for 3-10x the happy-path cost. Runaway spending is the #1 operational risk for multi-hour tasks.

11. **Observe everything.** If you can't see what the agent is doing, you can't fix it when it goes wrong. Traces, metrics, and structured logs are table stakes for production use.

12. **Secure by default.** Treat all external content as untrusted. Use least-privilege permissions. Require idempotency for external operations. The agent has the same attack surface as a remote code execution endpoint -- because that's what it is.

### The Session Protocol (Universal)

```
ORIENT  -> SETUP -> VERIFY -> SELECT -> IMPLEMENT -> TEST -> UPDATE -> EXIT
```
